# CLAUDE.md

คำแนะนำสำหรับ Claude Code เวลาทำงานกับโค้ดในโฟลเดอร์นี้

## ภาพรวมโปรเจค

Frontend ของ "เว็บไซต์อ่านฉลากยาสามัญประจำบ้าน" (OTC Medicine Label Scanning and
Safety Verification System) — ปริญญานิพนธ์ ทีม 2 คน

ผู้ใช้ถ่ายภาพฉลากยาหรือค้นหาด้วยชื่อยา ระบบแสดงข้อบ่งใช้ ขนาดการใช้ และคำเตือน
กลุ่มผู้ใช้หลักรวมผู้สูงอายุ จึงต้องอ่านง่าย ปรับขนาดตัวอักษรได้ และฟังเสียงได้
ไม่มีระบบบัญชีผู้ใช้ทั่วไป มีแค่ Admin ที่ต้อง login เพื่อจัดการข้อมูลยา

## คำสั่งที่ใช้บ่อย

```
python -m http.server 5173 --directory frontend
```

เปิด http://localhost:5173

หรือใช้ Live Server ของ VS Code ก็ได้ ตั้งค่าไว้ให้แล้วใน .vscode/settings.json

**ต้องเปิดที่ http://localhost:5173 หรือ http://localhost:3000 เท่านั้น**
เพราะฝั่ง Backend อนุญาตให้เรียกข้ามต้นทางได้แค่สองที่อยู่นี้
กับที่อยู่จริงบน Vercel สองที่คือ medcheck-frontend-psi.vercel.app และ medcheck-mu.vercel.app
ที่อยู่ Preview ของ Vercel ยังไม่ได้อนุญาต ถ้าต้องใช้ต้องแจ้งแพรเพิ่มให้ก่อน

ข้อควรระวังสองข้อ ถ้าผิดข้อใดข้อหนึ่งการเรียก /scan จะถูกเบราว์เซอร์ปฏิเสธด้วยกฎข้ามต้นทาง

1) พอร์ตต้องเป็น 5173 หรือ 3000 พอร์ตอื่นเช่น 5500 หรือ 5501 ที่ Live Server ใช้เป็นค่าตั้งต้นใช้ไม่ได้
2) ต้องพิมพ์ localhost เท่านั้น ใช้ 127.0.0.1 แทนไม่ได้ ถึงจะเป็นเครื่องเดียวกัน
   แต่เบราว์เซอร์ถือว่าเป็นคนละต้นทาง ตรวจแล้วว่า http://127.0.0.1:5173 ก็ยังถูกปฏิเสธ

ถ้าจำเป็นต้องใช้ที่อยู่อื่นจริง ๆ ต้องขอให้ฝั่ง Backend เพิ่มให้ก่อน

ห้ามเปิดด้วยการดับเบิลคลิกไฟล์ เพราะเบราว์เซอร์จะปฏิเสธการอ่าน data/drugs.json
และคำสั่งเรียกกล้องกับไมโครโฟนต้องการ HTTPS หรือ localhost เท่านั้น

## สถาปัตยกรรม

- index.html — หน้าเดียวครอบทุกหน้าย่อย แต่ละหน้าเป็น section.view ที่สลับด้วยแอตทริบิวต์ hidden
- css/ — เรียง 5 ไฟล์ tokens, base, shell, components, pages
- js/config.js — ที่อยู่ของ Backend และสวิตช์เลือกแหล่งข้อมูลยา
- js/data.js — โหลดข้อมูลยาจากฐานข้อมูล จัดรูปข้อความให้ค้นได้ และอ่านเขียนที่เก็บข้อมูลในเบราว์เซอร์
- js/app.js — ไอคอน เส้นทาง การแสดงผลทุกหน้า การค้นหา เสียง กล้อง และการเรียก Backend
- data/drugs.json — สำเนาข้อมูลยาไว้ใช้สำรองตอนเซิร์ฟเวอร์ล่ม ไม่ใช่แหล่งหลักแล้ว
- admin.html + css/admin.css + js/admin.js — หน้าจัดการข้อมูลสำหรับผู้ดูแลระบบ แยกจากเว็บหลัก
- assets/ — ไอคอนแท็บเบราว์เซอร์กับภาพพรีวิวตอนแชร์ลิงก์ · สร้างจากโลโก้เดิม ไม่ใช่ข้อมูลยา

og:image ใน index.html ยังเป็นที่อยู่แบบสั้น เมื่อรู้โดเมนจริงแล้วต้องเปลี่ยนเป็น https://... เต็ม ไม่งั้นแอปแชทกับเฟซบุ๊กจะดึงภาพไม่ขึ้น

ลำดับการเรียกไฟล์ CSS ใน index.html ห้ามสลับ เพราะ tokens ประกาศตัวแปรสีและขนาด
ที่ไฟล์ถัดไปทั้งหมดอ้างถึง และ pages ต้องอยู่ท้ายสุดเพื่อให้ทับค่าของไฟล์ก่อนหน้าได้

เรียกไฟล์ JavaScript ตามลำดับ config.js, data.js, app.js เสมอ
เพราะ app.js เรียกใช้ค่าและฟังก์ชันที่นิยามไว้ในสองไฟล์แรก

## แหล่งข้อมูลยาของเว็บหลัก

ตั้งแต่ต่อฐานข้อมูลแล้ว หน้าเว็บผู้ใช้อ่านรายการยาจาก API ไม่ได้อ่านจาก data/drugs.json อีก
สวิตช์อยู่ที่ DATA_FROM_API ใน config.js ตั้ง true คืออ่านจากฐานข้อมูล ตั้ง false คือกลับไปอ่านไฟล์
ตัวแปร dataSource ใน data.js บอกว่ารอบนั้นอ่านจากไหน มีค่า api หรือ file และขึ้นในคอนโซลตอนเปิดเว็บ

loadDB() เรียกสามเส้นทางตามลำดับ /categories แล้ว /medicines/by-category ของทุกหมวด
แล้ว /medicines/{id} ของยาทุกตัวแบบขนาน จากนั้นแปลงคำตอบให้เป็นรูปแบบเดียวกับ drugs.json
ทั้ง app.js จึงไม่ต้องแก้สักบรรทัด ถ้าจะเพิ่มช่องข้อมูลใหม่ ให้แปลงที่ data.js ที่เดียวเหมือนเดิม

ฐานข้อมูลไม่มีบางช่องที่ไฟล์เคยมี data.js จึงเติมให้เองดังนี้
- ชื่อย่อ คำอธิบาย ไอคอน และลำดับของหมวด มาจากตาราง CAT_META ที่เขียนไว้ใน data.js
- dosage_form ในฐานข้อมูลเป็นภาษาอังกฤษ แปลเป็นไทยด้วยตาราง FORM_TH
  บางตำรับเก็บหลายรูปแบบในช่องเดียวคั่นด้วย / เช่น COMPRESSED TABLET / TABLET
  ต้องแยกแปลทีละส่วนแล้วต่อกลับ ไม่งั้นจะหาในตารางไม่เจอแล้วขึ้นเป็นภาษาอังกฤษ
- packaging เดาจากรูปแบบยา ถ้าเข้าเงื่อนไข RE_LIQUID ถือเป็นขวด นอกนั้นเป็นแผง
- ระดับความแรงของคำเตือนเดาจากข้อความด้วย RE_DANGER คำว่าห้าม อันตราย เป็นพิษ ถือเป็นระดับอันตราย
- status ตั้งเป็น active ทุกรายการ สถานะทะเบียนจริงให้ดูจาก /verify เท่านั้น
- dosageAdult เป็นค่าว่าง เพราะฐานข้อมูลเก็บวิธีใช้รวมไว้ช่องเดียว

ข้อมูลสองฝั่งต่างกันอยู่บ้าง ฐานข้อมูลมียา 8 สูตรตำรับ ส่วนไฟล์มี 9
ที่ขาดคือยาน้ำโซเดียมอัลจิเนต ส่วนยี่ห้อมี 23 รายการเท่ากันทั้งสองฝั่ง
คำเตือนในฐานข้อมูลเก็บเป็นข้อความรวมต่อยาหนึ่งตัว ไม่ได้แยกเป็นข้อ ๆ เหมือนในไฟล์

ระหว่างรอข้อมูล app.js จะขึ้นแผ่นทับด้วย dataPane() และถอดออกด้วย hideDataPane()
ห้ามเขียนทับ innerHTML ของ #main เพื่อแสดงสถานะรอ เพราะจะลบ section.view ที่ตัวจัดเส้นทางต้องใช้
ถ้าโหลดไม่สำเร็จจะมีปุ่มลองใหม่ที่เรียก retryLoad() โดยไม่ต้องรีเฟรชทั้งหน้า

## ลิงก์ไปเว็บ อย. · ตรวจแล้วว่าทำไม่ได้ (16 พฤศจิกายน 2569)

เคยคิดจะใส่ลิงก์จากหน้ายาไปหน้าของยาตัวนั้นบนเว็บ อย. **ทำไม่ได้ ไม่ต้องลองใหม่**
เพราะ อย. ไม่มี URL รายตัวยาเลยสักระบบ

- `porta.fda.moph.go.th/fda_search_center_new` เป็น Angular ค้นด้วย POST ไปที่
  `FDA_SEARCH_CENTER_BACKEND/SEACH_ALL/GET_SEARCH` · ค้นเสร็จ URL ไม่เปลี่ยน
  กดปุ่มดูรายละเอียดก็ไม่เปลี่ยน · ลอง `?kw=` `?q=` `?search=` `?keyword=` แล้วระบบไม่รับ
- `pertento.fda.moph.go.th/FDA_SEARCH_DRUG/SEARCH_DRUG/FRM_SEARCH_DRUG.aspx`
  เป็น ASP.NET WebForms `method="post"` + ViewState ลิงก์ตรงไม่ได้เหมือนกัน
  และหน้านั้นเขียนเตือนเองว่าบน android หรือ ios อาจดูรายละเอียดไม่ได้ จึงไม่เหมาะกับเว็บเรา

ถ้าวันหลังจะทำ ทำได้แค่พาไปหน้าค้นหาแล้วคัดลอกเลขทะเบียนให้ผู้ใช้ไปวางเอง
ช่องค้นหาของ อย. รับเลขที่มีเว้นวรรคแบบที่เก็บไว้ได้เลย ไม่ต้องแปลงรูปแบบ
ตรวจแล้วว่าเลขทะเบียนในฐานข้อมูลตรงกับ อย. จริง เช่น `1A 822/43` ได้ ซาร่า ของไทยนครพัฒนา
และ `2C 90/50` ได้ กาวิสคอน เปปเปอร์มิ้นท์ ชนิดเม็ด ของเรกคิทท์ เบนคีเซอร์ สถานะคงอยู่ทั้งคู่

## โครงสร้าง data/drugs.json

```
categories[]    id, name, short, icon, order
formulations[]  id, categoryId, name, genericTh, genericEn, ingredients[], indications[],
                dosage, dosageAdult, warnings[], dosageForm, dosageFormEn, packaging
brands[]        id, formulationId, categoryId, productName, licensee, regNo, legalType,
                status, statusLabel, dosageForm, dosageFormEn, packaging, override
meta            sourceNote, updatedAt, references[]
```

ยาหนึ่งสูตรตำรับมีได้หลายยี่ห้อ ข้อมูลที่ใช้แสดงผลรวมมาจาก formulation เป็นหลัก
แต่ถ้ายี่ห้อนั้นมี override ให้ใช้ของยี่ห้อแทน ฟังก์ชัน content() ใน data.js จัดการให้แล้ว
ห้ามอ่านค่าจาก formulation หรือ brand ตรง ๆ โดยข้าม content()

**ห้ามแก้ไขข้อมูลยาใน drugs.json เอง** เป็นข้อมูลที่ทีมตรวจสอบกับทะเบียนยา อย. แล้ว
ถ้าพบข้อมูลผิดให้แจ้ง ไม่ต้องแก้ให้

## กับดักที่เคยเจอมาแล้ว อย่าทำซ้ำ

- `$` และ `$$` ใน app.js เป็นฟังก์ชันที่เขียนขึ้นเอง ไม่ใช่ jQuery โปรเจคนี้ไม่ใช้ไลบรารีใดเลย
- ข้อความทุกตัวที่มาจาก drugs.json หรือจากผู้ใช้ ต้องผ่าน esc() ก่อนต่อเป็นสตริง HTML เสมอ
- สร้างข้อความ HTML ทั้งก้อนให้เสร็จก่อน แล้วเขียนลง DOM ครั้งเดียว อย่าเขียนทีละรายการในลูป
- ผูกเหตุการณ์ด้วยการมอบหมายที่อิลิเมนต์แม่ เพราะรายการยาและปุ่มกลุ่มอาการถูกสร้างหลังโหลดข้อมูล
  ถ้าผูกตรงกับอิลิเมนต์ลูกตั้งแต่ต้น จะไม่ทำงานกับของที่สร้างทีหลัง
- การเทียบข้อความค้นหาต้องผ่าน norm() และเลขทะเบียนต้องผ่าน regKey() เสมอ ห้ามเทียบตรงตัว
  เพราะชื่อยาไทยมีสระและวรรณยุกต์ที่พิมพ์ต่างกันได้ และผู้ใช้พิมพ์เลขทะเบียนไม่เหมือนกัน
- ตรวจการรองรับของเบราว์เซอร์ก่อนเรียกใช้ความสามารถพิเศษเสมอ ได้แก่ SpeechRecognition,
  speechSynthesis และ mediaDevices ถ้าไม่รองรับให้ซ่อนปุ่มนั้นไปเลย อย่าปล่อยให้กดแล้วเงียบ
- route() ต้องคืนทรัพยากรที่ค้างอยู่ทุกครั้งที่เปลี่ยนหน้า ปัจจุบันเรียก stopSpeech() และ camClose()
  ถ้าเพิ่มความสามารถที่ถือทรัพยากรไว้ ต้องเพิ่มการปิดตรงนี้ด้วย
- คำตอบที่รอนาน เช่น /verify ต้องถือตัวอิลิเมนต์ไว้เป็นตัวแปร ห้ามค้นจาก id ตอนคำตอบกลับมา
  เพราะถ้าผู้ใช้ถ่ายใหม่ระหว่างรอ คำตอบของภาพเก่าจะไปเขียนทับกล่องของภาพใหม่
- ใช้คลาสที่มีอยู่แล้วก่อนเขียนสไตล์ใหม่ โดยเฉพาะ state, state-ico, state-actions, btn, rows, notice
  หน้าตาจะตรงกับหน้าอื่นทันทีและรองรับโหมดสีเข้มอยู่แล้ว
- **ป้าย `.pill` ตั้งขอบบนมากกว่าขอบล่างโดยตั้งใจ** `padding:.45rem .8rem .35rem`
  เห็นแล้วอย่าจัดให้เท่ากัน ฟอนต์ไทยกันที่ว่างข้างบนไว้ให้วรรณยุกต์ แต่ข้อความส่วนใหญ่
  ไม่มีสระล่าง ที่ว่างนั้นจึงเหลือค้าง ตัวอักษรเลยดูลอยไปติดขอบบน
  **ค่านี้ผูกกับฟอนต์หัวข้อ เปลี่ยนฟอนต์เมื่อไหร่ต้องวัดใหม่ทุกครั้ง** ที่วัดมาแล้ว
  IBM Plex Sans Thai (descent 7) ใช้ `.55/.25` เบี้ยวสุด 3.9px
  Prompt (descent 6) ใช้ `.5/.3` เบี้ยวสุด 4.1px
  Anuphan (descent 4) ใช้ `.45/.35` เบี้ยวสุด 3.5px คือค่าปัจจุบัน
  เทียบกับแบบขอบเท่ากันซึ่งเบี้ยวถึง 8.7px
  `.pill svg` ต้องมี `top:-.05rem` คู่กันเสมอ เพราะไอคอนไม่มีเรื่องวรรณยุกต์
  ถ้าไม่ดึงกลับ ไอคอนจะถูกดันลงไปพร้อมตัวอักษรจนหลุดกลางป้าย
  ค่าที่ดึงกลับเท่ากับครึ่งหนึ่งของผลต่างขอบบนลบขอบล่าง เปลี่ยนระยะขอบต้องเปลี่ยนตาม
  `.drugrow-b .pill` ในหน้าแอดมินวัดแยกต่างหาก ได้ `.38/.12` เบี้ยวสุด 1.4px
  ค่าต่างกันเพราะตัวอักษรเล็กกว่า อย่าคัดลอกค่าข้ามกัน
  `.drugrow-b .pill` ใน admin.css ใช้หลักเดียวกัน แต่ย่อระยะตามขนาดตัวอักษรที่เล็กกว่า
  **เป็นเรื่องระยะขอบล้วน ๆ ห้ามแก้ด้วย `line-height`** ตัวนั้นเปลี่ยนแค่ความสูงป้าย
  ไม่ได้ขยับตัวอักษรในป้ายเลย และจะไปทำให้ป้ายที่ขึ้นสองบรรทัดบนจอมือถือบรรทัดติดกัน
- สีทุกสีต้องอ้างผ่านตัวแปรใน tokens.css ห้ามใส่ค่าสีตรง ๆ ในไฟล์อื่น เพราะโหมดสีเข้มจะเพี้ยน
- ขนาดตัวอักษรใช้หน่วยสัมพัทธ์เสมอ เพราะปุ่มปรับขนาดทำงานด้วยการเปลี่ยนขนาดพื้นฐานของเอกสาร

## หน้าเพิ่มยาในหน้าแอดมิน อ่านก่อนแก้

ฟอร์มนี้รื้อมาแล้วสี่รอบ เพราะคนกรอกข้อมูลจริงอ่านไม่เข้าใจ ข้อกำหนดด้านล่างมาจากคนใช้โดยตรง

- **หน้าแอดมินมีสองหน้า** คือหน้าแรกที่เป็นการ์ดเลือกงาน กับหน้าจัดการข้อมูลที่เป็นตารางรายการยา
  สลับด้วยตัวแปร `view` (`'home'` หรือ `'list'`) ผ่าน `goView()` ซึ่งถามก่อนถ้ามีฟอร์มค้างอยู่
  **การ์ดทั้งสามใบเป็นงานที่ผู้ดูแลต้องทำ ไม่ใช่ตารางในฐานข้อมูล** คือ จัดการข้อมูลยา · เพิ่มยาใหม่ ·
  หน้าเว็บสำหรับผู้ใช้ **คำบนการ์ดต้องเป็นภาษาทางการ และห้ามเอ่ยถึงโครงสร้างฝั่งเซิร์ฟเวอร์**
  ไม่ใช้คำว่า ตาราง สูตรตำรับ เอนด์พอยต์ หรือชื่อตารางใด ๆ ให้ผู้กรอกอ่าน
- **ห้ามเอาแท็บกลับมา** เคยมีสามแท็บตามสามตารางของฐานข้อมูล คือ ผลิตภัณฑ์ · สูตรตำรับ · ตัวยาสำคัญ
  แล้วคนกรอกต้องไล่กรอกทีละแท็บโดยต้องเข้าใจก่อนว่าสามตารางนั้นเกี่ยวกันอย่างไร ซึ่งไม่ผ่าน
  โครงสร้างสามตารางยังอยู่ฝั่งเซิร์ฟเวอร์เหมือนเดิม แต่หน้าเว็บต้องซ่อนไว้ทั้งหมด
  **หน้าแรกที่เอากลับมาคือการ์ดเลือกงาน ไม่ใช่แท็บ** การ์ดพาไปที่เดียวกันหมดคือหน้าจัดการข้อมูล
- **ฟอร์มที่เปิดอยู่กินพื้นที่ทั้งหน้า ห้ามเอากลับไปแทรกกลางรายการ**
  `formPane()` เป็นตัวสร้าง และ `productPage()` เป็นตัวตัดสินว่าจะวาดฟอร์มหรือวาดตาราง
  `productRow()` จึงไม่รู้จักโหมดแก้ไขแล้ว อย่าใส่กลับเข้าไป
  ตอนที่ฟอร์มปนอยู่กับรายการ มีทางให้สิ่งที่กรอกไว้หายเงียบ ๆ สองทาง
  กดปุ่มเพิ่มใหม่ขณะกำลังแก้อยู่ `openNew()` เขียนทับ `form` ทั้งก้อนโดยไม่เตือน
  และพิมพ์ค้นหาจนแถวที่แก้อยู่หลุดจากผลค้น แถวจะหายไปจากจอโดยไม่บอกอะไร
  **จงใจไม่ทำเป็นเส้นทาง URL แยก** เพราะต้องไปสู้กับปุ่มย้อนกลับของเบราว์เซอร์
  และเรื่องข้อมูลที่ยังค้างในฟอร์ม ซึ่งเกินความจำเป็น

  และต้องเขียนลงช่องกรอกทันทีในฟังก์ชันนั้นเลย ไม่งั้นรอบอ่านถัดไปจะอ่านค่าเก่าจากหน้าจอกลับมาทับ

  ชื่อที่เดาให้มีปริมาณตัวยาอยู่ด้วย เช่น `พาราเซตามอล 500 mg · ยาเม็ด` จึงแยกความแรงออกจากกันได้เอง
  และถ้าไปซ้ำกับชุดที่มีอยู่ **ต้องต่อท้ายด้วยชื่อยี่ห้อ** เช่น `(เฉพาะ พาราแคป 325)`
- **เจอชุดข้อมูลที่ตรงกัน ให้เติมข้อความให้เลย ไม่ต้องถาม** `autoShare()` เติมเฉพาะตอนสามช่องล่างยังว่าง
  ถ้าพิมพ์ข้อความไว้ก่อนแล้วค่อยกรอกตัวยาจนตรง จะไม่ทับของที่พิมพ์ แต่ขึ้นปุ่มเสนอที่ `offerNote()` แทน
  **ปุ่มนั้นไม่บังคับตอบ** กดบันทึกโดยไม่แตะปุ่มได้ เพราะถ้าบังคับตอบ คนจะกดเพื่อให้ข้อความเตือนหาย
  ไม่ใช่เพราะเทียบกับกล่องยาแล้วตรงจริง ซึ่งอันตรายกว่าไม่มีปุ่ม
- **สามช่อง ข้อบ่งใช้ วิธีใช้ คำเตือน เป็นช่องกรอกเสมอ** ห้ามทำเป็นอ่านอย่างเดียวอีก
  เคยทำแล้วต้องกดออกไปแก้ที่แท็บอื่น ซึ่งทิ้งฟอร์มที่กรอกค้างไว้
  เมื่อยี่ห้ออื่นใช้ข้อมูลชุดเดียวกันอยู่ `noteSlot()` ขึ้นกล่องเหลืองบอกรายชื่อที่จะเปลี่ยนตาม
  **ต้องบอกให้ชัดเสมอ** เพราะเป็นการแก้ข้อมูลของยาตัวอื่นไปด้วย
- **เลือกพิมพ์ข้อความเอง แล้วข้อมูลไปอยู่ที่ `medicine` แถวใหม่ ไม่ใช่ที่ `brand`**
  `saveMedPart()` ยิง `POST /admin/medicines` สร้างชุดข้อมูลที่ยี่ห้อนั้นใช้คนเดียว
  แล้วค่อย `POST /admin/brands` ผูก `medicine_id` มาที่แถวนั้น
  ที่ต้องทำแบบนี้เพราะตาราง `brand` ยังไม่มีช่องเก็บข้อความรายยี่ห้อ
  **เป็นทางอ้อม ไม่ใช่ปลายทางที่ตั้งใจ** ถ้าวันหนึ่งได้คอลัมน์ override มาแล้ว
  ให้เปลี่ยนเส้นทางนี้ไปเขียนที่ `brand` แทน จะได้ไม่เก็บข้อความซ้ำหลายแถว
- **ลบผลิตภัณฑ์ที่เป็นยี่ห้อสุดท้ายของชุดข้อมูล จะลบชุดข้อมูลตามไปด้วย**
  เพราะไม่มีแท็บสูตรตำรับให้เห็นของที่ค้างอีกแล้ว กล่องยืนยันต้องบอกเรื่องนี้ตรง ๆ ทุกครั้ง
  ถ้ายังมียี่ห้ออื่นใช้อยู่ ลบแค่แถวใน `brands` และต้องบอกว่ายี่ห้ออื่นยังอยู่ครบ
- **ช่องตัวยาผูก `change` ห้ามใช้ `input`** และ **ห้ามให้มันวาดฟอร์มใหม่ทั้งฟอร์ม**
  ให้เรียก `refreshIng()` ซึ่งวาดใหม่แค่ `#ingList` กับ `#noteSlot`
  ถ้าวาดใหม่ทั้งฟอร์ม การกดปุ่มบันทึกตอนที่เคอร์เซอร์ยังอยู่ในช่องตัวยาจะหลุด
  เพราะ `change` ทำงานตอนคลิกลง แล้วปุ่มถูกสร้างใหม่ก่อนที่คลิกจะจบ
- **ปริมาณตัวยาเก็บรายตัวใน `form.ingStr`** เป็น ไอดีตัวยา -> ข้อความ
  เทียบกันแบบไม่สนตัวพิมพ์เล็กใหญ่และช่องว่างซ้ำ ที่ `normStr()`
  **สะกดต่างกัน เช่น `500 mg` กับ `500 มก.` ถือว่าคนละชุด โดยตั้งใจ**
  ยอมพลาดไปทางไม่จับคู่ ดีกว่าจับคู่ผิดแล้วได้ขนาดรับประทานของยาคนละความแรง
- **ส่ง `ingredients` ไม่ใช่ `ingredient_ids`** แบบเดิมไม่ล้างปริมาณเดิมให้
  ซึ่งจะทำให้ลบปริมาณที่กรอกผิดไว้ออกไม่ได้เลย
- **`adultDose()` ใน `js/data.js`** ดึงขนาดของผู้ใหญ่ออกจาก `dosage_instructions`
  เพราะ API ไม่มีช่องนี้แยกไว้ ใช้เติม `dosageAdult` ที่การ์ดสรุปใน `app.js` ต้องใช้
  ตั้งกติกาไว้เข้มโดยตั้งใจ คือต้องเจอคำว่าผู้ใหญ่ ตัดที่คำว่าเด็กหรือทารก
  (ยกเว้นที่ต่อท้ายคำว่าและ ซึ่งเป็นขนาดร่วมกัน) ต้องมีตัวเลข และต้องไม่ยาวเกิน 110 ตัวอักษร
  **ไม่เข้าเกณฑ์ให้คืนค่าว่าง** การ์ดจะไม่ขึ้น ซึ่งดีกว่าขึ้นขนาดยาที่ไม่แน่ใจ
  ทดสอบกับทั้ง 9 สูตรใน `data/drugs.json` แล้วตรงกับค่าที่คนเขียนไว้ทุกตัว
  ถ้าจะแก้ตรรกะนี้ ต้องรันเทียบกับ `dosageAdult` ในไฟล์นั้นใหม่ทุกครั้ง
- **ดอกจันบอกช่องที่ต้องกรอก เขียน `*` ต่อท้ายข้อความป้าย แค่นั้น**
  `field()` `fieldArea()` `fieldSelect()` เรียก `lbl()` ซึ่งดึงดอกจันออกมาเป็น
  `<span class="req" aria-hidden="true">` เพื่อระบายสีแดงได้ แล้วเติม `aria-required`
  ให้ตัวช่องเองผ่าน `reqAttr()` **ห้ามพิมพ์ `*` ลงใน `<label>` ตรง ๆ**
  ที่ต้องซ่อนดอกจันจากโปรแกรมอ่านหน้าจอ เพราะมันอ่านว่า ดาว ซึ่งไม่ได้ความหมายอะไร
  ความหมายว่าบังคับกรอกสื่อผ่าน `aria-required` แทน
- **ช่องที่แบบร่างมี แต่ฐานข้อมูลยังไม่มีคอลัมน์** คือ บรรจุภัณฑ์ (เช่น แผงละ 10 เม็ด)
  และ การเก็บรักษา **ตัดออกจากฟอร์มไปก่อน ห้ามเอาไปยัดรวมในช่องอื่น**
  คอลัมน์ `รูปแบบยา` ในตารางรายการใช้ `dosage_form` ไม่ใช่บรรจุภัณฑ์ อย่าสลับความหมายกัน
  ถ้าจะใส่ ต้องขอให้ Backend เพิ่มคอลัมน์ `packaging` กับ `storage` ก่อน
- **ตาราง `brand` ยังไม่มีช่องเก็บข้อบ่งใช้ วิธีใช้ คำเตือน เฉพาะยี่ห้อ**
  (ส่วน `strength` แพรเพิ่มให้แล้วใน revision 00006 · 16 พฤศจิกายน 2569)
  `content(b)` ใน `js/data.js` อ่าน `override` อยู่แล้วและ `data/drugs.json` ก็ใช้อยู่จริง
  แต่ฝั่ง API ยังส่ง `override: {}` ตายตัว ต้องรอแพรเพิ่มคอลัมน์ รายละเอียดอยู่ใน `scratchpad` ของรอบนั้น
  **เรื่องนี้สำคัญกว่าที่คิด** คำเตือนของยาสูตรเดียวกันไม่ได้เหมือนกันทุกยี่ห้อจริง
  ตรวจกับข้อมูลต้นทางแล้วเจอว่า BELCID FORTE มีคำเตือนยาวกว่ายี่ห้ออื่นที่ตัวยาตรงกัน

## การเข้าถึงได้ ต้องรักษาไว้

กลุ่มผู้ใช้หลักรวมผู้สูงอายุและผู้ที่มองเห็นไม่ชัด สิ่งที่ทำไว้แล้วและห้ามทำหาย

- ปรับขนาดตัวอักษร 3 ระดับ และโหมดสีเข้ม
- ใช้งานได้ครบด้วยแป้นพิมพ์ มีกรอบบอกตำแหน่งที่กำลังใช้งาน และมีลิงก์ข้ามไปเนื้อหาหลัก
- ข้อความสถานะใช้ aria-live เพื่อให้โปรแกรมอ่านหน้าจอประกาศ
- ปุ่มที่เป็นไอคอนล้วนต้องมีชื่อกำกับด้วย aria-label
- ลดการเคลื่อนไหวเมื่อผู้ใช้ตั้งค่าเครื่องให้ลดการเคลื่อนไหว

## ถ้อยคำที่แสดงต่อผู้ใช้

เป็นงานด้านยาและอ้างอิงทะเบียนของ อย. ข้อความทุกจุดจึงใช้ภาษาเขียนที่เป็นทางการ
ไม่ใช้ภาษาพูด และไม่พูดถึงระบบเหมือนมีชีวิต ข้อตกลงที่ใช้อยู่

- คำขอร้องใช้ **โปรด** เท่านั้น ไม่ใช้ กรุณา เพื่อให้เหมือนกันทั้งเว็บ
- ใช้ **รับประทาน** ไม่ใช้ กิน · ใช้ **หาก** ไม่ใช้ ถ้า · ใช้ **หลีกเลี่ยง** ไม่ใช้ เลี่ยง
- ใช้ **นำออก** ไม่ใช้ เอาออก · ใช้ **ไม่สามารถ...ได้** ไม่ใช้ ...ไม่ได้ ในข้อความแจ้งผล
- เลี่ยงคำว่า แค่ เพียงแค่ ง่ายๆ และคำลงท้ายแบบ ก็ได้
- จุดไข่ปลาใช้อักขระ `…` ไม่ใช่จุดสามจุด และอัญประกาศใช้ `“ ”` ไม่ใช่ `" "`
- ห้ามบรรยายเซิร์ฟเวอร์เหมือนคน เช่น ตื่นจากการพักเครื่อง ให้เขียนว่า
  **กำลังเริ่มทำงานจากสถานะพัก**
- หัวข้อใช้คำนาม ไม่ใช้ประโยคคำถาม เช่น ขอบเขตของระบบ ไม่ใช่ ระบบครอบคลุมอะไรบ้าง
- ข้อความแจ้งความผิดพลาดบอกทั้ง **สาเหตุ** และ **ทางแก้** เสมอ
  เช่น ไม่พบกล้องในอุปกรณ์นี้ โปรดเลือกภาพจากเครื่องแทน

ข้อความใน `data/drugs.json` ไม่อยู่ในข้อตกลงนี้ เพราะคัดมาจากฉลากและทะเบียนยาตามจริง
ห้ามขัดเกลาถ้อยคำส่วนนั้น

**ใต้ชื่อยาไม่มีบรรทัดอะไรเลย ห้ามใส่กลับ** ผู้ใช้สั่งเอาออกเมื่อ 20 พฤศจิกายน 2569
เคยมีบรรทัด `.res-gen` แสดง รูปแบบยา · ชื่อสามัญ อยู่สั้น ๆ ตอนทำแบบเอกสารกำกับยารอบแรก
แต่ยาที่มีตัวยาหลายตัว เช่น กาวิสคอน ที่มีสามตัว บรรทัดนี้ยาวจนตกสองบรรทัด
แล้วหัวข้อตัวยาสำคัญที่อยู่ถัดลงไปก็ขึ้นสามตัวเดิมซ้ำอีกรอบทันที พร้อมปริมาณซึ่งละเอียดกว่า
**เคยลองย้ายรูปแบบยาไปเป็นป้ายในแถวบนสุด ผู้ใช้ให้เอาออกแล้ว ห้ามทำซ้ำ**
ป้ายใบที่สี่ทำให้แถวป้ายตกสองบรรทัด แล้วปุ่ม ฟังข้อมูลยา หล่นไปอยู่บรรทัดล่างคนเดียว เกิดแถบว่าง
**ผลที่ตามมาที่ต้องรู้** หน้าเว็บไม่แสดง รูปแบบยา ที่ไหนเลย
`thForm()` กับตาราง `FORM_TH` ใน `js/data.js` จึงไม่มีใครเรียกใช้แล้ว **แต่ห้ามลบทิ้ง**
เผื่อวันหนึ่งต้องเอารูปแบบยากลับมาแสดง และหน้าแอดมินยังมีตารางคู่กันอยู่ที่ต้องตรงกัน
ค่า `genericTh` `genericEn` ยังต้องมีอยู่ ใช้ค้นหา ใช้ในกล่องผลค้นหา ใช้อ่านออกเสียง
และ `ingredientsTh()` ก็อ่าน `genericTh` เพื่อเอาชื่อไทยมาจับคู่ **ห้ามลบค่าพวกนี้ทิ้ง**

## ขนาดและวิธีใช้ อ่านก่อนแก้

- **หัวข้อนี้แสดงข้อความจากฐานข้อมูลตรง ๆ ทีละบรรทัด ห้ามเขียนพาดหัวสรุปเพิ่ม**
  เคยมีการ์ดที่พาดหัวว่า สำหรับผู้ใหญ่ แล้วขึ้นข้อความที่พูดถึงเด็กด้วย ซึ่งขัดกันเองต่อหน้าคนอ่าน
  ฉลากยาบางตัวเขียนขนาดของผู้ใหญ่กับเด็กโตรวมกันเป็นบรรทัดเดียว
  เช่น `ผู้ใหญ่และเด็กอายุ 12 ปีขึ้นไป ครั้งละ 2-4 เม็ด` ในฐานข้อมูลจริงมีสองสูตรแบบนี้ คือ id 3 กับ id 9
  **ระบบไม่มีทางรู้ว่าบรรทัดไหนของใคร** จึงต้องแสดงตามที่กรอกไว้ ไม่ตีความแทนคนอ่าน
- **`adultDose()` เหลือที่ใช้ที่เดียวคือข้อความอ่านออกเสียง** (`js/app.js` ตัวแปร `c.dosageAdult`)
  **จงใจไม่ตัดคำว่า เด็ก ทิ้งเมื่อมี และ นำหน้า** เพราะนั่นคือขนาดที่ใช้ร่วมกัน
  ไม่ใช่ขนาดของเด็กคนละอัน ตัดทิ้งเมื่อไหร่จะได้ขนาดผู้ใหญ่ที่ไม่ครบความหมาย
  ส่วน `เด็ก 6-12 ปี ...` ที่ขึ้นบรรทัดใหม่หรือไม่มี และ นำหน้า ต้องตัดทิ้งเหมือนเดิม
- **`b.packaging` ไม่ได้มาจากฐานข้อมูล** `js/data.js` เดาจาก `dosage_form` ด้วย `RE_LIQUID`
  ไม่ใช่ของเหลวก็ตอบ blister หมด · ไฟล์ `data/drugs.json` เคยเก็บค่านี้จริงรายยี่ห้อ
  แต่ตาราง `brand` ฝั่ง API ไม่มีช่องนี้ จึงแก้ในหน้าแอดมินไม่ได้
  **ที่เหลืออยู่คือไอคอนแผงยากับขวดยาในกล่องผลค้นหาเท่านั้น** (`js/app.js` บรรทัดราว 727)
  **ห้ามเอามาแสดงเป็นข้อความในหน้าข้อมูลยา** เพราะเป็นค่าที่เดาเอา ไม่ใช่ข้อมูลจากทะเบียน

### เวลาจะเปลี่ยนรูป

ส่งออก svg จากโปรแกรมวาดรูปไว้ในโฟลเดอร์ไหนก็ได้ แล้วชี้สคริปต์ไปที่โฟลเดอร์นั้น

```
python -I tools/make-cat-icons.py "C:\Users\user\Downloads\โฟลเดอร์ที่เพิ่งโหลดมา"
```

สคริปต์จะคัดไฟล์ที่ต้องการมาใส่ `assets/src/` ให้เอง แล้วสร้าง `assets/cat-icons.svg` ต่อทันที
**ไม่ต้องเปลี่ยนชื่อไฟล์เอง** เทียบจากคำสำคัญในชื่อไฟล์ ดูตาราง `ICONS` ในสคริปต์
ไฟล์ที่มีคำว่า white ในชื่อจะถูกข้ามอัตโนมัติ และส่งมาไม่ครบหกอันก็ได้
อันที่ไม่ได้ส่งมา จะใช้ของเดิมใน `assets/src/` ต่อ

ถ้าไฟล์อยู่ใน `assets/src/` ด้วยชื่อที่ถูกต้องอยู่แล้ว รันเปล่า ๆ ได้เลย

```
python -I tools/make-cat-icons.py
```

จากนั้นรีเฟรชเว็บ ไม่ต้องแก้โค้ดที่ไหนเลย

- **ถ้าชื่อไฟล์ที่ส่งออกมาไม่มีคำสำคัญตรงกับตาราง `ICONS` สคริปต์จะข้ามไปเงียบ ๆ**
  ดูบรรทัด `คัดมา` ที่สคริปต์พิมพ์ออกมาทุกครั้ง ถ้าไม่มีชื่อไอคอนที่ตั้งใจเปลี่ยน แปลว่าไม่ได้ถูกคัดมา
  แก้ได้สองทาง คือเปลี่ยนชื่อไฟล์ให้มีคำสำคัญ หรือเพิ่มคำสำคัญใหม่ลงในตาราง `ICONS`

สคริปต์จะตัด `<defs>` กับ `clipPath` ที่โปรแกรมวาดรูปใส่มาแต่ไม่ได้ใช้ออก
วัดขอบเขตของรูปจริงแล้วย่อให้พอดีกรอบ 24x24 เท่ากับไอคอนตัวอื่นในเว็บ
และเปลี่ยนสีที่ฝังมาในไฟล์เป็น `currentColor`

- **ไฟล์ต้นฉบับห้ามใส่สีมากกว่าหนึ่งสี** สคริปต์เปลี่ยนทุกสีเป็น `currentColor` หมด
  เพราะไอคอนต้องเปลี่ยนสีตามที่ใช้ · การ์ดกลุ่มอาการเป็นสีหลัก ปุ่มกรองที่เลือกอยู่เป็นสีขาว
  โหมดมืดใช้แดงอ่อนกว่าโหมดสว่าง ถ้าฝังสีตายตัวไว้ โหมดมืดจะทึบจนแทบมองไม่เห็น
- **ชุดสีขาวใน `assets/src/*-white.svg` ไม่ได้ใช้งานแล้ว** ตอนนี้สีขาวมาจาก `currentColor` เอง
  เก็บไว้เป็นต้นฉบับเฉย ๆ จะลบทิ้งก็ได้
- **รูปเส้นชุดเดิมหกตัวในตาราง `P` ที่ต้น `js/app.js` ห้ามลบ** เป็นตัวสำรอง
  ถ้าโหลด `assets/cat-icons.svg` ไม่สำเร็จ `svg()` จะใช้รูปเส้นชื่อเดียวกันแทน เว็บจะไม่มีช่องว่าง
- **ชื่อทั้งหกต้องตรงกันสามที่** คือ `CAT_ICONS` ใน `js/app.js` · `id` ใน `assets/cat-icons.svg`
  · และ `icon` ของกลุ่มอาการที่มาจากฐานข้อมูล ถ้าไม่ตรง จะตกไปใช้รูปเส้นสำรองเงียบ ๆ

### บทเรียนตอนวาดรูปเส้น เก็บไว้เผื่อต้องวาดใหม่

- **ขนาดที่ต้องผ่านคือไอคอนในปุ่มกรอง ไม่ใช่ในการ์ด** ลายเส้นที่ละเอียดเกินจะเละตรงนั้นก่อน
  เวลาวาดใหม่ ต้องดูที่ขนาดเล็กเสมอ ดูแต่ขนาดใหญ่แล้วผ่าน ไม่พอ
- **ห้ามวาดปากเป็นทรงเลนส์นอน คือวงรีแหลมสองหัวมีเส้นกลาง** ลองมาแล้วสี่แบบ
  ทุกแบบคนอ่านเป็นดวงตา ไม่ใช่ปาก ผู้ใช้ตีกลับทั้งหมด
- **จมูกต้องเป็นมุมมองหน้าตรง ไม่ใช่ด้านข้าง** จมูกด้านข้างเป็นเส้นเปิดเส้นเดียว
  ย่อแล้วอ่านเป็นขอเกี่ยวหรือเครื่องหมายคำถาม ลองมาแล้วหลายขนาด ไม่รอด
- **ทรงโค้งเปิดปลายอ่านเป็นตัวอักษรไทย** ลำไส้ที่วาดเป็นเส้นโค้งห้าแบบ
  ถูกอ่านเป็น ก อ ป ค ที่ขนาดเล็กทุกแบบ
- **ไอคอนเส้นมีทั้ง `<path>` และ `<circle>` ได้** ตัวห่อใส่ `fill="none"` ไว้ที่ `<svg>` ชั้นนอก
  วงกลมจึงออกมาเป็นเส้นขอบ ไม่ใช่วงทึบ

  ไอคอนกินความกว้างปุ่มละราว 2rem ทั้งที่ชื่อกลุ่มอาการบอกครบอยู่แล้ว
  ค่า `c.icon` ยังต้องมีอยู่ ใช้ที่การ์ดกลุ่มอาการในหน้าหลัก (`.catcard-ico`) **ห้ามลบทิ้ง**
- **ชื่อเต็มกับชื่อย่ออยู่ในปุ่มเดียวกัน สลับด้วย CSS ไม่ใช่ JS** `.t-full` กับ `.t-mini`
  จอกว้างกว่า 30rem ใช้ `short` จอแคบกว่านั้นใช้ `mini` จาก `CAT_META` ใน `js/data.js`
  ถ้าใช้ชื่อเต็มบนมือถือจะตก 6 บรรทัด สูง 290px ดันผลการค้นหาหลุดลงไปใต้จอ ชื่อย่อเหลือ 4 บรรทัด 191px
  ที่ทำด้วย CSS เพราะไม่ต้องวาดปุ่มใหม่ตอนหมุนจอ และตัวที่ `display:none` ไม่ถูกอ่านซ้ำโดยโปรแกรมอ่านหน้าจอ
  **เพิ่มกลุ่มอาการใหม่เมื่อไหร่ ต้องใส่ `mini` ด้วย** ไม่ใส่จะตกไปใช้ชื่อเต็มแล้วมือถือยาวเกิน
- **ปุ่มที่เลือกใช้ `--cta` ไม่ใช่ `--primary`** โหมดมืด `--primary` คือ #F2444C
  ซึ่งสว่างเกินกว่าจะวางตัวหนังสือขาวได้ ค่าความต่างแค่ 3.7 ต่อ 1 ไม่ถึงเกณฑ์ 4.5
  `--cta` โหมดมืดเป็น #C8141D ได้ 5.9 ต่อ 1 ส่วนโหมดสว่างสองตัวนี้ค่าเท่ากัน จึงเห็นเหมือนเดิม
- **ไม่ใช้ `toneVars()` กับปุ่มกรองแล้ว** ใช้สีหลักสีเดียวทุกกลุ่ม
  สีประจำกลุ่ม `--c1` ถึง `--c6` ยังใช้อยู่ที่การ์ดกลุ่มอาการหน้าแรกและรายการแนะนำ
  เหตุผลเดียวกับกล่องผลการค้นหาด้านล่าง
- `syncChips()` ไม่ต้องเลื่อนปุ่มที่เลือกมากลางแถบอีกแล้ว เพราะไม่มีการเลื่อนแนวนอน

## เส้นทางหน้าเว็บกับการกดรีเฟรช อ่านก่อนแก้

หน้าเว็บเปลี่ยนหน้าด้วย `history.pushState` ที่ `go()` ใน `js/app.js`
ที่อยู่อย่าง `/drug/10/dose` หรือ `/category/2` **ไม่มีไฟล์อยู่จริงบนเซิร์ฟเวอร์**
`parseHash()` เป็นตัวอ่าน `location.pathname` ตอนเปิดหน้า เส้นทางลึกจึงใช้ได้ ถ้าเซิร์ฟเวอร์ส่ง index.html มาให้

ถ้าไม่ตั้งค่าให้เซิร์ฟเวอร์ส่ง index.html พอผู้ใช้กดรีเฟรช หรือก๊อบลิงก์ไปเปิดใหม่ จะเจอ
`Cannot GET /drug/10/dose` หรือ 404 ทันที

- **ตอนพัฒนา** ตั้ง `"liveServer.settings.file": "index.html"` ใน `.vscode/settings.json`
  ส่วนขยาย Live Server อธิบายค่านี้ไว้ว่า ส่งไฟล์นี้ให้ทุก 404
  ตัวมันทำงานทีหลังตัวเสิร์ฟไฟล์จริง ไฟล์ที่มีอยู่จริงอย่าง `/css/tokens.css` จึงยังได้ของเดิม
  **ผลข้างเคียงที่ต้องรู้** ไฟล์ที่พิมพ์ชื่อผิดจะได้ index.html กลับมาพร้อมสถานะ 200 ไม่ใช่ 404
  ถ้าเจออาการ css ไม่มา ทั้งที่ขึ้น 200 ให้สงสัยชื่อไฟล์ผิดก่อน
- **ตอนขึ้นเว็บจริง** ไฟล์ `frontend/vercel.json` เป็นตัวตั้งกติกาเดียวกัน
  **ไฟล์นี้ต้องอยู่ในโฟลเดอร์ `frontend/` เท่านั้น** เพราะโปรเจกต์ใน Vercel ตั้ง Root Directory
  ไว้ที่ `frontend` · Vercel อ่าน `vercel.json` จาก Root Directory ไม่ใช่จากรากของ repo
  เคยวางไว้ที่รากของ repo แล้วเว็บจริง 404 ทุกเส้นทางลึก ทั้งที่ไฟล์เขียนถูกทุกอย่าง
- กติกาที่เขียนไว้คือ ส่ง index.html ให้ทุกเส้นทาง ยกเว้นที่ขึ้นต้นด้วย
  `css/` `js/` `data/` `assets/` `favicon` `admin`
  **เพิ่มโฟลเดอร์ใหม่ที่ต้องเสิร์ฟไฟล์ตรง ๆ เมื่อไร ต้องมาเติมชื่อในรายการนี้ด้วย**
  ไม่งั้นไฟล์ในโฟลเดอร์นั้นจะกลายเป็น index.html ทั้งหมด

## กล่องผลการค้นหา ตอนเอาเมาส์ชี้

- **ใช้สีหลักของเว็บสีเดียว ห้ามแยกสีตามกลุ่มอาการ** อยู่ที่ `.row:hover` ใน `css/components.css`
  สีประจำกลุ่มอาการ `--c1` ถึง `--c6` มีหน้าที่บอกหมวดอยู่ที่ป้ายในกล่องแล้ว
  ถ้าเอามาทาขอบกล่องด้วย กล่องจะเปลี่ยนสีไปมาทั้งหน้า จนไม่เหลือสัญญาณว่ากล่องไหนกำลังถูกชี้
- **พื้นกล่องต้องเป็น `--surface` เหมือนเดิม ห้ามย้อมสีพื้นตอนชี้**
  ป้ายกลุ่มอาการใช้ `--tint-2` ซึ่งอ่อนมาก ถ้าพื้นกล่องกลายเป็น `--tint` ป้ายจะกลืนหายไปกับพื้น
  สีที่ใช้บอกว่ากำลังชี้อยู่คือ ขอบกล่อง แถบสีด้านซ้าย และลูกศรขวามือ
- **หน้าตาต้องตรงกับการ์ดกลุ่มอาการ `.catcard` ใน `css/pages.css`** ผู้ใช้สั่งไว้
  ยกตัวขึ้น 4px · เงา `--sh-2` เปล่า ๆ ไม่เจือสี · ขอบเปลี่ยนสี · แถบสีซ้าย 5px ยืดขึ้นจากล่าง
  แก้ที่ไหน ต้องไปแก้อีกที่ให้ตรงกันด้วย ไม่งั้นสองหน้าจะชี้แล้วขยับคนละแบบ
- **ต่างจาก `.catcard` อยู่จุดเดียว คือสี** การ์ดกลุ่มอาการใช้สีประจำกลุ่ม `--cc` ได้
  เพราะหนึ่งใบคือหนึ่งกลุ่ม แต่รายการผลค้นหาปนหลายกลุ่มอยู่ในลิสต์เดียว
  ถ้าแต่ละแถวเปลี่ยนสีตามกลุ่ม ลิสต์จะอ่านเป็นลายพร้อย
- แถบสีซ้ายตั้งใจให้บาง 5px เท่ากับการ์ดกลุ่มอาการ ไม่ใช่พลาด
  ถ้าจะทำให้หนาขึ้น ต้องไปเพิ่มที่การ์ดกลุ่มอาการพร้อมกัน
- `:focus-visible` ได้หน้าตาเดียวกับ `:hover` คนที่ใช้คีย์บอร์ดต้องเห็นว่าอยู่กล่องไหน

## รูปแบบยาและการแสดงภาษาไทย

ค่าที่เก็บในฐานข้อมูลเป็น**ภาษาอังกฤษ**ตามคำในทะเบียนตำรับยา อย. เช่น `EFFERVESCENT POWDER`
ส่วนที่ผู้ใช้เห็นต้องเป็น**ภาษาไทยล้วน** ไม่พ่วงคำอังกฤษไว้ข้างหลัง

- ตัวเลือกใน `<select>` ใช้ `value` เป็นคีย์อังกฤษ และป้ายที่แสดงเป็นไทยเท่านั้น
- `formOptions()` และ `ingLabel()` ใน `js/admin.js` ห้ามต่อ `' · ' + ชื่ออังกฤษ` เข้าไปอีก
- ถ้าตัวยาไม่มีชื่อไทย ให้ใช้ชื่ออังกฤษแทนได้ เป็นทางออกสุดท้ายไม่ใช่ค่าปกติ
- ชื่ออังกฤษของตัวยายังต้องกรอกตอนสร้างตัวยาใหม่ เพราะเป็นคีย์ที่ระบบสแกนใช้จับคู่ฉลาก
  แต่ป้ายที่แสดงในรายการตัวยาที่จับคู่ได้ ใช้ชื่อไทยอย่างเดียว
- หัวหน้าข้อมูลยาฝั่งผู้ใช้เคยมีบรรทัด `.res-en` แสดงชื่อการค้าและชื่อสามัญภาษาอังกฤษ
  **เอาออกแล้วโดยตั้งใจ อย่าใส่กลับ** คนอ่านฉลากยาที่บ้านอ่านภาษาไทย
  ตอนนี้ใต้ชื่อยาไม่มีบรรทัดอะไรเลย เหตุผลอยู่ในหัวข้อ ถ้อยคำในหน้าเว็บ

**ตาราง FORM_TH มีสองชุด ต้องตรงกันเสมอ**

| ไฟล์ | ใช้กับ |
|---|---|
| `js/admin.js` | ตัวเลือกและรายการในหน้าจัดการข้อมูล |
| `js/data.js` | หน้าเว็บฝั่งผู้ใช้ |

เพิ่มรูปแบบยาใหม่ต้องเพิ่มทั้งสองไฟล์ ถ้าเพิ่มแค่ไฟล์เดียว ฝั่งที่ตกหล่นจะแสดงคำอังกฤษดิบ
(เคยพลาดมาแล้วตอนเพิ่ม `EFFERVESCENT POWDER` ให้อีโน)

**ป้ายไทยห้ามซ้ำกัน** เพราะไม่มีชื่ออังกฤษต่อท้ายให้แยกแล้ว
เดิม `ORAL SOLUTION` กับ `ORAL LIQUID` แปลว่า ยาน้ำสำหรับรับประทาน เหมือนกันทั้งคู่
แก้เป็น `ORAL SOLUTION` = ยาน้ำใสสำหรับรับประทาน ให้เข้าชุดกับ `SOLUTION` = ยาน้ำใส

## การเชื่อมกับ Backend

Backend ขึ้นใช้งานจริงแล้วที่ https://medcheck-api-1052579662255.asia-southeast1.run.app
ที่อยู่นี้เขียนไว้ที่ js/config.js ที่เดียว ย้ายเซิร์ฟเวอร์เมื่อไรแก้ไฟล์นั้นไฟล์เดียว
ตั้ง USE_MOCK เป็น true เมื่ออยากทดสอบหน้าเว็บโดยไม่เรียกเซิร์ฟเวอร์จริง

โครงการนี้ไม่มีขั้นตอนแปลงไฟล์ ไฟล์ถูกส่งขึ้นเว็บตามที่เขียนไว้เลย
จึงใช้ environment variable แบบ import.meta.env ของ Vite ไม่ได้ ต้องเขียนค่าไว้ใน config.js
ที่อยู่เซิร์ฟเวอร์ไม่ใช่ความลับ เครื่องผู้ใช้เห็นอยู่แล้วตอนเรียกใช้งาน จึงเขียนตรง ๆ ได้
แต่กุญแจการเข้าถึงบริการยังห้ามใส่ฝั่งนี้เด็ดขาด

ตั้ง USE_MOCK เป็น true เมื่ออยากทดสอบหน้าถ่ายรูปโดยไม่เรียกเซิร์ฟเวอร์จริง
รายการยาและการค้นหาอ่านจากฐานข้อมูลแล้ว ดูหัวข้อแหล่งข้อมูลยาของเว็บหลักข้างบน

### POST /scan

ส่งภาพเป็น multipart ชื่อช่องต้องเป็น file ถ้าใช้ชื่ออื่นจะได้รหัส 422
ห้ามตั้งหัวข้อ Content-Type เอง เบราว์เซอร์ต้องเติมเส้นแบ่งข้อมูลให้เอง

```
match_type   reg_no | brand_name | active_ingredient | out_of_scope | not_found
ocr_text     ข้อความทั้งหมดที่อ่านได้จากฉลาก
ocr_reg_no   เลขทะเบียนที่อ่านได้ หรือ null
brand        { id, brand_name, licensee, reg_no, legal_type, medicine_id } หรือ null
medicine     ข้อมูลยาเต็มรูปแบบเดียวกับ /medicines/{id} หรือ null
candidates   [ brand + medicine_name ] เมื่อจับคู่ได้หลายยี่ห้อ
```

ฝั่งนี้ใช้ match_type กับเลขทะเบียน แล้วเอาเลขทะเบียนไปค้นใน DB ด้วย brandByReg()
ไม่ได้ใช้ medicine ที่ส่งมา เพราะโครงสร้างต่างกับที่หน้าเว็บใช้แสดงผล
ใช้เลขทะเบียนเป็นตัวเชื่อม เพราะวิธีนี้ยังทำงานได้ทั้งตอนอ่านจากฐานข้อมูลและตอนอ่านจากไฟล์สำรอง
ตรวจแล้วว่าเลขทะเบียนทั้ง 23 ยี่ห้อตรงกันทั้งสองฝั่ง

### GET /verify/{brand_id}

ตรวจสถานะทะเบียนกับเว็บ อย. ใช้ brand.id ที่ /scan ส่งมา ไม่ใช่ id ในไฟล์ฝั่งนี้
เรียกหลังแสดงข้อมูลยาให้ผู้ใช้เห็นแล้วเสมอ เพราะระบบของ อย. ตอบช้าได้ถึงประมาณครึ่งนาที
ห้ามให้ทั้งหน้ารอผลการตรวจ

อ่านคำตอบตามลำดับนี้ ok ก่อน แล้ว found แล้ว is_active
ok:false คือติดต่อ อย. ไม่ได้ ซึ่งยังได้รหัส 200 ไม่ใช่ 502

### ข้อตกลงร่วมของทุกเส้นทาง

ข้อความผิดพลาดอยู่ที่ detail เป็นภาษาไทย นำไปแสดงผู้ใช้ได้เลย
ยกเว้นรหัส 422 ที่ detail เป็นรายการ ไม่ใช่ข้อความ ฟังก์ชัน errText() ใน app.js จัดการให้แล้ว
ฝั่งแอดมินใช้ detailText() ใน admin.js ทำหน้าที่เดียวกัน

ตั้งแต่คู่มือฉบับ 13 พ.ย. 2569 รหัส 500 ส่งหัวข้อข้ามต้นทางกับ detail กลับมาด้วยแล้ว
เบราว์เซอร์จึงอ่านได้ ไม่ขึ้นเป็น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้" เหมือนก่อน
สองฟังก์ชันข้างบนรองรับอยู่แล้ว ไม่ต้องแก้อะไรเพิ่ม

เซิร์ฟเวอร์จะหลับเมื่อไม่มีคนใช้ คำขอแรกจึงช้าได้ 5-10 วินาที ไม่ใช่ความผิดพลาด
หน้าถ่ายรูปจะขึ้นข้อความบอกผู้ใช้เองเมื่อรอเกิน 7 วินาที

### เส้นทางที่ใช้โหลดรายการยา

/categories, /medicines/by-category, /medicines/{id} เรียกจาก loadDB() ใน data.js
ส่วน /medicines/search ยังไม่ได้ใช้ เพราะฝั่งนี้ค้นในเครื่องได้เร็วกว่าและใช้ตอนเน็ตหลุดได้

เปิดเว็บครั้งแรกต้องยิงประมาณ 15 คำขอ ตอนเซิร์ฟเวอร์เพิ่งตื่นวัดได้ราว 16 วินาที
ตอนเซิร์ฟเวอร์ตื่นอยู่แล้ววัดได้ราว 0.4 วินาที จึงต้องมีแผ่นทับบอกสถานะเสมอ

## หน้าจัดการข้อมูล (admin.html)

เป็นไฟล์แยกจากเว็บหลัก ไม่ได้อยู่ในเมนูและไม่ได้ใช้ตัวจัดเส้นทางเดียวกัน เปิดที่ /admin.html

`render()` เลือกตามตัวแปร `view` แล้วเรียก `setHead()` เปลี่ยนหัวเรื่องในหน้าให้ตรงกัน

#viewApp เป็น flex column สูงเต็มจอ และ #adminMain เป็น flex:1 เพื่อดันท้ายหน้า

**ตารางรายการยา** คือตาราง brands หนึ่งแถวคือหนึ่งผลิตภัณฑ์ที่ผู้ใช้เห็นในหน้าค้นหา
คอลัมน์คือ ชื่อผลิตภัณฑ์ยา (มีชื่อสามัญกับผู้ผลิตเป็นบรรทัดรอง) · หมวดหมู่ · เลขทะเบียน อย. ·
รูปแบบยา · ปุ่มแก้ไขกับลบ จอแคบกว่า 720px ตารางคลี่เป็นบล็อกทีละรายการด้วย CSS
**ห้ามให้ตารางเลื่อนซ้ายขวาบนมือถือ** ข้อมูลยาที่อ่านไม่ครบอันตรายกว่าบล็อกที่ยาวขึ้น

ช่องค้นหาค้นจากชื่อผลิตภัณฑ์ ชื่อสามัญ ผู้ผลิต หมวดหมู่ และเลขทะเบียน
(พิมพ์มีหรือไม่มีช่องว่างก็ได้) ข้างกันเป็นตัวกรองหมวดหมู่ เก็บคำตอบไว้ที่ตัวแปร `cat`
ตัวเลือกมาจาก `catOptions()` ซึ่งนับจำนวนผลิตภัณฑ์ในแต่ละหมวดให้ด้วย

หนึ่งแถวเกิดจากสองตารางรวมกัน brands เก็บชื่อการค้า เลขทะเบียน ผู้ผลิต ประเภทตามกฎหมาย
ส่วน medicines เก็บ หมวดหมู่ ชื่อสามัญ รูปแบบยา ตัวยาสำคัญ ข้อบ่งใช้ วิธีใช้ คำเตือน
ฟอร์มเดียวแก้ทั้งสองตาราง **ผู้กรอกไม่ต้องรู้ว่าช่องไหนอยู่ตารางไหน และไม่ต้องรู้จักคำว่าสูตรตำรับ**

**แถวใน medicines ใช้ร่วมกันได้หลายผลิตภัณฑ์** เช่นยาพาราเซตามอลหลายยี่ห้อใช้ชุดเดียวกัน
แก้ช่องของชุดนั้นจึงเปลี่ยนให้ทุกผลิตภัณฑ์ที่ใช้อยู่ ฟอร์มขึ้นกล่องเหลืองบอกรายชื่อที่จะเปลี่ยนตาม
ตอนเพิ่มใหม่ ถ้าตัวยาสำคัญ ปริมาณ และรูปแบบยา ตรงกับชุดที่มีอยู่ ระบบจะดึงมาใช้ร่วมแทนการสร้างซ้ำ

**ตอนบันทึกจะส่ง PUT ของ medicines ก็ต่อเมื่อช่องของชุดนั้นเปลี่ยนจริง** เทียบจาก form.base
เพิ่มผลิตภัณฑ์ใหม่เข้าชุดเดิม หรือแก้แค่ผู้ผลิตกับเลขทะเบียน จะยิงแค่เส้นทาง brands เส้นเดียว
ลำดับการส่งเป็นไปตามที่ฐานข้อมูลต้องการคือ ตัวยาสำคัญ แล้ว medicines แล้ว brands

**ลบผลิตภัณฑ์ที่เป็นยี่ห้อสุดท้ายของชุดนั้น จะลบแถวใน medicines ตามไปด้วย**
เพราะไม่มีหน้าไหนให้เห็นชุดที่ไม่มีใครใช้แล้วอีก ถ้าไม่ลบตามจะค้างในฐานข้อมูลโดยไม่มีทางเห็นหรือลบ
ถ้ายังมียี่ห้ออื่นใช้อยู่ ลบแค่แถวใน brands

**ตัวยาสำคัญกรอกทีละแถวในฟอร์มยาเลย** ชื่อตัวยากับปริมาณแยกช่องกัน ไม่มีหน้าจัดการตัวยาแยกแล้ว
ตัวที่ยังไม่มีในระบบจะถูกสร้างให้ตอนกดบันทึก ผ่าน POST /admin/ingredients
**ที่ยังทำไม่ได้จากหน้าเว็บคือแก้ชื่อตัวยาที่สร้างไปแล้ว และลบตัวยาออกจากระบบ**
ชื่อเรียกอื่นก็ยังเพิ่มจากหน้านี้ไม่ได้ ทั้งที่ระบบสแกนใช้จับคู่ฉลากที่พิมพ์ชื่อตัวยาคนละแบบ
ถ้าพิมพ์ชื่อตัวยาผิดแล้วบันทึกไป ต้องให้ Backend แก้ให้ ถ้าเรื่องนี้เกิดบ่อย
ค่อยเติมปุ่มดินสอเล็ก ๆ ในแถวตัวยาที่จับคู่ได้ **ห้ามแก้ด้วยการเอาแท็บตัวยาสำคัญกลับมา**

**ช่องที่แบบที่ออกแบบไว้มีแต่ฐานข้อมูลยังไม่มีคอลัมน์** คือ การเก็บรักษา และปริมาณของตัวยาแต่ละตัว
ตกลงกันว่าตัดออกจากฟอร์มไปก่อน ถ้าจะใส่ต้องขอให้ Backend เพิ่มคอลัมน์ storage
และเพิ่มช่องปริมาณในตารางที่เชื่อม medicine กับ ingredient ก่อน ห้ามเอาไปยัดรวมในช่องอื่น

**ผู้รับอนุญาตไม่มีตารางของตัวเอง** licensee เป็นข้อความอยู่ในแต่ละแถวของ brands
แก้ชื่อผู้ผลิตจึงมีผลเฉพาะผลิตภัณฑ์นั้นตัวเดียว ถ้าพิมพ์ชื่อบริษัทไม่ตรงกันจะกลายเป็นคนละรายทันที
ถ้าวันหนึ่งต้องเก็บที่อยู่หรือเลขที่ใบอนุญาตด้วย ต้องขอให้ Backend ทำตารางแยกแล้วให้ brands อ้างด้วย licensee_id

**ต่อกับ API จริงแล้ว** ทุกอย่างในหน้านี้อ่านและเขียนผ่านเส้นทาง /admin ของ Backend
ไม่มีข้อมูลจำลองและไม่มีสำเนาในเบราว์เซอร์อีกแล้ว สิ่งที่บันทึกมีผลกับผู้ใช้ทุกคนทันที
ที่อยู่เซิร์ฟเวอร์อยู่ที่ API_BASE ใน config.js ไฟล์เดียว ห้ามเขียนที่อยู่ซ้ำในไฟล์อื่น

เส้นทางที่หน้านี้ใช้
- GET /categories · GET /admin/me
- /admin/medicines (GET, GET/{id}, POST, PUT/{id}, DELETE/{id})
- /admin/brands (GET, POST, PUT/{id}, DELETE/{id})
- /admin/ingredients (GET, POST)

ข้อตกลงของ API ที่ต้องระวัง
- สูตรตำรับส่งแก้ไขด้วย PUT ที่ต้องมีครบทุกช่องทุกครั้ง · medBody() ประกอบก้อนนั้นให้
  ช่องไหนหายไปจากฟอร์ม ช่องนั้นจะถูกล้างในฐานข้อมูล จึงห้ามตัดช่องออกจากฟอร์มโดยไม่คิด
- warnings กับ ingredient_ids เป็นแบบ "แทนที่ทั้งชุด" ไม่มีเส้นทางแก้ทีละข้อ
  หน้าเว็บจึงแก้ในหน่วยความจำก่อนแล้วส่งทั้งอาร์เรย์
- indications ฝั่งเซิร์ฟเวอร์เป็นข้อความก้อนเดียว หน้านี้ให้กรอกทีละข้อแล้วต่อด้วยขึ้นบรรทัดใหม่
  ด้วย lines() กับ unline() ถ้าเปลี่ยนตัวคั่นต้องแก้สองฟังก์ชันนี้คู่กัน
- เลขทะเบียนซ้ำเซิร์ฟเวอร์ตอบ 409 พร้อมข้อความไทย หน้านี้ตรวจซ้ำให้ก่อนตั้งแต่ในเครื่อง
  เพราะโหลด /admin/brands มาทั้งหมดอยู่แล้ว แต่ยังต้องรับ 409 ไว้เสมอ เผื่อมีคนเพิ่มพร้อมกัน
- ลบ medicines ที่ยังมีผลิตภัณฑ์อ้างอยู่เซิร์ฟเวอร์ตอบ 409 · `delProduct()` จึงลบ brand ก่อนเสมอ
  แล้วค่อยลบ medicine และถ้าขั้นที่สองพลาด ไม่ต้องขัดจังหวะ เพราะยี่ห้อถูกลบไปแล้วจริง
- ลบสำเร็จได้ 204 ไม่มี body · api() คืน null ให้

**การเข้าสู่ระบบเป็นของจริงแล้ว** ใช้ POST /admin/login แบบฟอร์ม ไม่ใช่ JSON
บัตรผ่านเก็บใน sessionStorage ชื่อ admin_token มีอายุ 8 ชั่วโมง
ทุกคำขอที่ขึ้นต้นด้วย /admin แนบหัว Authorization: Bearer ให้อัตโนมัติใน api()
ถ้าได้ 401 จะลบบัตรผ่านแล้วพากลับหน้าเข้าสู่ระบบพร้อมข้อความบอกเหตุผล
ห้ามเก็บชื่อผู้ใช้ รหัสผ่าน หรือเงื่อนไขการตรวจสิทธิ์ไว้ในไฟล์ฝั่งนี้เด็ดขาด
บัญชีผู้ดูแลสร้างจากฝั่ง Backend เท่านั้น ไม่มีหน้าสมัครสมาชิก
