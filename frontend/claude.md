# CLAUDE.md

คำแนะนำสำหรับ Claude Code เวลาทำงานกับโค้ดในโฟลเดอร์นี้

## ภาพรวมโปรเจค

Frontend ของ "เว็บไซต์อ่านฉลากยาสามัญประจำบ้าน" (OTC Medicine Label Scanning and
Safety Verification System) — ปริญญานิพนธ์ ทีม 2 คน

ผู้ใช้ถ่ายภาพฉลากยาหรือค้นหาด้วยชื่อยา ระบบแสดงข้อบ่งใช้ ขนาดการใช้ และคำเตือน
กลุ่มผู้ใช้หลักรวมผู้สูงอายุ จึงต้องอ่านง่าย ปรับขนาดตัวอักษรได้ และฟังเสียงได้
ไม่มีระบบบัญชีผู้ใช้ทั่วไป มีแค่ Admin ที่ต้อง login เพื่อจัดการข้อมูลยา

## คำสั่งที่ใช้บ่อย

```
python -m http.server 5173 --directory frontend
```

เปิด http://localhost:5173

หรือใช้ Live Server ของ VS Code ก็ได้ ตั้งค่าไว้ให้แล้วใน .vscode/settings.json

**ต้องเปิดที่ http://localhost:5173 หรือ http://localhost:3000 เท่านั้น**
เพราะฝั่ง Backend อนุญาตให้เรียกข้ามต้นทางได้แค่สองที่อยู่นี้กับที่อยู่จริงบน Vercel

ข้อควรระวังสองข้อ ถ้าผิดข้อใดข้อหนึ่งการเรียก /scan จะถูกเบราว์เซอร์ปฏิเสธด้วยกฎข้ามต้นทาง

1) พอร์ตต้องเป็น 5173 หรือ 3000 พอร์ตอื่นเช่น 5500 หรือ 5501 ที่ Live Server ใช้เป็นค่าตั้งต้นใช้ไม่ได้
2) ต้องพิมพ์ localhost เท่านั้น ใช้ 127.0.0.1 แทนไม่ได้ ถึงจะเป็นเครื่องเดียวกัน
   แต่เบราว์เซอร์ถือว่าเป็นคนละต้นทาง ตรวจแล้วว่า http://127.0.0.1:5173 ก็ยังถูกปฏิเสธ

ถ้าจำเป็นต้องใช้ที่อยู่อื่นจริง ๆ ต้องขอให้ฝั่ง Backend เพิ่มให้ก่อน

ห้ามเปิดด้วยการดับเบิลคลิกไฟล์ เพราะเบราว์เซอร์จะปฏิเสธการอ่าน data/drugs.json
และคำสั่งเรียกกล้องกับไมโครโฟนต้องการ HTTPS หรือ localhost เท่านั้น

## สถาปัตยกรรม

- index.html — หน้าเดียวครอบทุกหน้าย่อย แต่ละหน้าเป็น section.view ที่สลับด้วยแอตทริบิวต์ hidden
- css/ — เรียง 5 ไฟล์ tokens, base, shell, components, pages
- js/config.js — ที่อยู่ของ Backend และสวิตช์เลือกแหล่งข้อมูลยา
- js/data.js — โหลดข้อมูลยาจากฐานข้อมูล จัดรูปข้อความให้ค้นได้ และอ่านเขียนที่เก็บข้อมูลในเบราว์เซอร์
- js/app.js — ไอคอน เส้นทาง การแสดงผลทุกหน้า การค้นหา เสียง กล้อง และการเรียก Backend
- data/drugs.json — สำเนาข้อมูลยาไว้ใช้สำรองตอนเซิร์ฟเวอร์ล่ม ไม่ใช่แหล่งหลักแล้ว
- admin.html + css/admin.css + js/admin.js — หน้าจัดการข้อมูลสำหรับผู้ดูแลระบบ แยกจากเว็บหลัก

ลำดับการเรียกไฟล์ CSS ใน index.html ห้ามสลับ เพราะ tokens ประกาศตัวแปรสีและขนาด
ที่ไฟล์ถัดไปทั้งหมดอ้างถึง และ pages ต้องอยู่ท้ายสุดเพื่อให้ทับค่าของไฟล์ก่อนหน้าได้

เรียกไฟล์ JavaScript ตามลำดับ config.js, data.js, app.js เสมอ
เพราะ app.js เรียกใช้ค่าและฟังก์ชันที่นิยามไว้ในสองไฟล์แรก

## แหล่งข้อมูลยาของเว็บหลัก

ตั้งแต่ต่อฐานข้อมูลแล้ว หน้าเว็บผู้ใช้อ่านรายการยาจาก API ไม่ได้อ่านจาก data/drugs.json อีก
สวิตช์อยู่ที่ DATA_FROM_API ใน config.js ตั้ง true คืออ่านจากฐานข้อมูล ตั้ง false คือกลับไปอ่านไฟล์
ตัวแปร dataSource ใน data.js บอกว่ารอบนั้นอ่านจากไหน มีค่า api หรือ file และขึ้นในคอนโซลตอนเปิดเว็บ

loadDB() เรียกสามเส้นทางตามลำดับ /categories แล้ว /medicines/by-category ของทุกหมวด
แล้ว /medicines/{id} ของยาทุกตัวแบบขนาน จากนั้นแปลงคำตอบให้เป็นรูปแบบเดียวกับ drugs.json
ทั้ง app.js จึงไม่ต้องแก้สักบรรทัด ถ้าจะเพิ่มช่องข้อมูลใหม่ ให้แปลงที่ data.js ที่เดียวเหมือนเดิม

ฐานข้อมูลไม่มีบางช่องที่ไฟล์เคยมี data.js จึงเติมให้เองดังนี้
- ชื่อย่อ คำอธิบาย ไอคอน และลำดับของหมวด มาจากตาราง CAT_META ที่เขียนไว้ใน data.js
- dosage_form ในฐานข้อมูลเป็นภาษาอังกฤษ แปลเป็นไทยด้วยตาราง FORM_TH
  บางตำรับเก็บหลายรูปแบบในช่องเดียวคั่นด้วย / เช่น COMPRESSED TABLET / TABLET
  ต้องแยกแปลทีละส่วนแล้วต่อกลับ ไม่งั้นจะหาในตารางไม่เจอแล้วขึ้นเป็นภาษาอังกฤษ
- packaging เดาจากรูปแบบยา ถ้าเข้าเงื่อนไข RE_LIQUID ถือเป็นขวด นอกนั้นเป็นแผง
- ระดับความแรงของคำเตือนเดาจากข้อความด้วย RE_DANGER คำว่าห้าม อันตราย เป็นพิษ ถือเป็นระดับอันตราย
- status ตั้งเป็น active ทุกรายการ สถานะทะเบียนจริงให้ดูจาก /verify เท่านั้น
- dosageAdult เป็นค่าว่าง เพราะฐานข้อมูลเก็บวิธีใช้รวมไว้ช่องเดียว

ข้อมูลสองฝั่งต่างกันอยู่บ้าง ฐานข้อมูลมียา 8 สูตรตำรับ ส่วนไฟล์มี 9
ที่ขาดคือยาน้ำโซเดียมอัลจิเนต ส่วนยี่ห้อมี 23 รายการเท่ากันทั้งสองฝั่ง
คำเตือนในฐานข้อมูลเก็บเป็นข้อความรวมต่อยาหนึ่งตัว ไม่ได้แยกเป็นข้อ ๆ เหมือนในไฟล์

ระหว่างรอข้อมูล app.js จะขึ้นแผ่นทับด้วย dataPane() และถอดออกด้วย hideDataPane()
ห้ามเขียนทับ innerHTML ของ #main เพื่อแสดงสถานะรอ เพราะจะลบ section.view ที่ตัวจัดเส้นทางต้องใช้
ถ้าโหลดไม่สำเร็จจะมีปุ่มลองใหม่ที่เรียก retryLoad() โดยไม่ต้องรีเฟรชทั้งหน้า

## โครงสร้าง data/drugs.json

```
categories[]    id, name, short, icon, order
formulations[]  id, categoryId, name, genericTh, genericEn, ingredients[], indications[],
                dosage, dosageAdult, warnings[], dosageForm, dosageFormEn, packaging
brands[]        id, formulationId, categoryId, productName, licensee, regNo, legalType,
                status, statusLabel, dosageForm, dosageFormEn, packaging, override
meta            sourceNote, updatedAt, references[]
```

ยาหนึ่งสูตรตำรับมีได้หลายยี่ห้อ ข้อมูลที่ใช้แสดงผลรวมมาจาก formulation เป็นหลัก
แต่ถ้ายี่ห้อนั้นมี override ให้ใช้ของยี่ห้อแทน ฟังก์ชัน content() ใน data.js จัดการให้แล้ว
ห้ามอ่านค่าจาก formulation หรือ brand ตรง ๆ โดยข้าม content()

**ห้ามแก้ไขข้อมูลยาใน drugs.json เอง** เป็นข้อมูลที่ทีมตรวจสอบกับทะเบียนยา อย. แล้ว
ถ้าพบข้อมูลผิดให้แจ้ง ไม่ต้องแก้ให้

## กับดักที่เคยเจอมาแล้ว อย่าทำซ้ำ

- `$` และ `$$` ใน app.js เป็นฟังก์ชันที่เขียนขึ้นเอง ไม่ใช่ jQuery โปรเจคนี้ไม่ใช้ไลบรารีใดเลย
- ข้อความทุกตัวที่มาจาก drugs.json หรือจากผู้ใช้ ต้องผ่าน esc() ก่อนต่อเป็นสตริง HTML เสมอ
- สร้างข้อความ HTML ทั้งก้อนให้เสร็จก่อน แล้วเขียนลง DOM ครั้งเดียว อย่าเขียนทีละรายการในลูป
- ผูกเหตุการณ์ด้วยการมอบหมายที่อิลิเมนต์แม่ เพราะรายการยาและปุ่มกลุ่มอาการถูกสร้างหลังโหลดข้อมูล
  ถ้าผูกตรงกับอิลิเมนต์ลูกตั้งแต่ต้น จะไม่ทำงานกับของที่สร้างทีหลัง
- การเทียบข้อความค้นหาต้องผ่าน norm() และเลขทะเบียนต้องผ่าน regKey() เสมอ ห้ามเทียบตรงตัว
  เพราะชื่อยาไทยมีสระและวรรณยุกต์ที่พิมพ์ต่างกันได้ และผู้ใช้พิมพ์เลขทะเบียนไม่เหมือนกัน
- ตรวจการรองรับของเบราว์เซอร์ก่อนเรียกใช้ความสามารถพิเศษเสมอ ได้แก่ SpeechRecognition,
  speechSynthesis และ mediaDevices ถ้าไม่รองรับให้ซ่อนปุ่มนั้นไปเลย อย่าปล่อยให้กดแล้วเงียบ
- route() ต้องคืนทรัพยากรที่ค้างอยู่ทุกครั้งที่เปลี่ยนหน้า ปัจจุบันเรียก stopSpeech() และ camClose()
  ถ้าเพิ่มความสามารถที่ถือทรัพยากรไว้ ต้องเพิ่มการปิดตรงนี้ด้วย
- คำตอบที่รอนาน เช่น /verify ต้องถือตัวอิลิเมนต์ไว้เป็นตัวแปร ห้ามค้นจาก id ตอนคำตอบกลับมา
  เพราะถ้าผู้ใช้ถ่ายใหม่ระหว่างรอ คำตอบของภาพเก่าจะไปเขียนทับกล่องของภาพใหม่
- ใช้คลาสที่มีอยู่แล้วก่อนเขียนสไตล์ใหม่ โดยเฉพาะ state, state-ico, state-actions, btn, rows, notice
  หน้าตาจะตรงกับหน้าอื่นทันทีและรองรับโหมดสีเข้มอยู่แล้ว
- สีทุกสีต้องอ้างผ่านตัวแปรใน tokens.css ห้ามใส่ค่าสีตรง ๆ ในไฟล์อื่น เพราะโหมดสีเข้มจะเพี้ยน
- ขนาดตัวอักษรใช้หน่วยสัมพัทธ์เสมอ เพราะปุ่มปรับขนาดทำงานด้วยการเปลี่ยนขนาดพื้นฐานของเอกสาร
  ถ้าใช้หน่วยคงที่ ข้อความส่วนนั้นจะไม่ขยายตาม

## การเข้าถึงได้ ต้องรักษาไว้

## การเชื่อมกับ Backend

Backend ขึ้นใช้งานจริงแล้วที่ https://medcheck-api-1052579662255.asia-southeast1.run.app
ที่อยู่นี้เขียนไว้ที่ js/config.js ที่เดียว ย้ายเซิร์ฟเวอร์เมื่อไรแก้ไฟล์นั้นไฟล์เดียว
ตั้ง USE_MOCK เป็น true เมื่ออยากทดสอบหน้าเว็บโดยไม่เรียกเซิร์ฟเวอร์จริง

โครงการนี้ไม่มีขั้นตอนแปลงไฟล์ ไฟล์ถูกส่งขึ้นเว็บตามที่เขียนไว้เลย
จึงใช้ environment variable แบบ import.meta.env ของ Vite ไม่ได้ ต้องเขียนค่าไว้ใน config.js
ที่อยู่เซิร์ฟเวอร์ไม่ใช่ความลับ เครื่องผู้ใช้เห็นอยู่แล้วตอนเรียกใช้งาน จึงเขียนตรง ๆ ได้
แต่กุญแจการเข้าถึงบริการยังห้ามใส่ฝั่งนี้เด็ดขาด

ตั้ง USE_MOCK เป็น true เมื่ออยากทดสอบหน้าถ่ายรูปโดยไม่เรียกเซิร์ฟเวอร์จริง
รายการยาและการค้นหาอ่านจากฐานข้อมูลแล้ว ดูหัวข้อแหล่งข้อมูลยาของเว็บหลักข้างบน

### POST /scan

ส่งภาพเป็น multipart ชื่อช่องต้องเป็น file ถ้าใช้ชื่ออื่นจะได้รหัส 422
ห้ามตั้งหัวข้อ Content-Type เอง เบราว์เซอร์ต้องเติมเส้นแบ่งข้อมูลให้เอง

```
match_type   reg_no | brand_name | active_ingredient | out_of_scope | not_found
ocr_text     ข้อความทั้งหมดที่อ่านได้จากฉลาก
ocr_reg_no   เลขทะเบียนที่อ่านได้ หรือ null
brand        { id, brand_name, licensee, reg_no, legal_type, medicine_id } หรือ null
medicine     ข้อมูลยาเต็มรูปแบบเดียวกับ /medicines/{id} หรือ null
candidates   [ brand + medicine_name ] เมื่อจับคู่ได้หลายยี่ห้อ
```

ฝั่งนี้ใช้ match_type กับเลขทะเบียน แล้วเอาเลขทะเบียนไปค้นใน DB ด้วย brandByReg()
ไม่ได้ใช้ medicine ที่ส่งมา เพราะโครงสร้างต่างกับที่หน้าเว็บใช้แสดงผล
ใช้เลขทะเบียนเป็นตัวเชื่อม เพราะวิธีนี้ยังทำงานได้ทั้งตอนอ่านจากฐานข้อมูลและตอนอ่านจากไฟล์สำรอง
ตรวจแล้วว่าเลขทะเบียนทั้ง 23 ยี่ห้อตรงกันทั้งสองฝั่ง

### GET /verify/{brand_id}

ตรวจสถานะทะเบียนกับเว็บ อย. ใช้ brand.id ที่ /scan ส่งมา ไม่ใช่ id ในไฟล์ฝั่งนี้
เรียกหลังแสดงข้อมูลยาให้ผู้ใช้เห็นแล้วเสมอ เพราะระบบของ อย. ตอบช้าได้ถึงประมาณครึ่งนาที
ห้ามให้ทั้งหน้ารอผลการตรวจ

อ่านคำตอบตามลำดับนี้ ok ก่อน แล้ว found แล้ว is_active
ok:false คือติดต่อ อย. ไม่ได้ ซึ่งยังได้รหัส 200 ไม่ใช่ 502

### ข้อตกลงร่วมของทุกเส้นทาง

ข้อความผิดพลาดอยู่ที่ detail เป็นภาษาไทย นำไปแสดงผู้ใช้ได้เลย
ยกเว้นรหัส 422 ที่ detail เป็นรายการ ไม่ใช่ข้อความ ฟังก์ชัน errText() ใน app.js จัดการให้แล้ว

เซิร์ฟเวอร์จะหลับเมื่อไม่มีคนใช้ คำขอแรกจึงช้าได้ 5-10 วินาที ไม่ใช่ความผิดพลาด
หน้าถ่ายรูปจะขึ้นข้อความบอกผู้ใช้เองเมื่อรอเกิน 7 วินาที

### เส้นทางที่ใช้โหลดรายการยา

/categories, /medicines/by-category, /medicines/{id} เรียกจาก loadDB() ใน data.js
ส่วน /medicines/search ยังไม่ได้ใช้ เพราะฝั่งนี้ค้นในเครื่องได้เร็วกว่าและใช้ตอนเน็ตหลุดได้

เปิดเว็บครั้งแรกต้องยิงประมาณ 15 คำขอ ตอนเซิร์ฟเวอร์เพิ่งตื่นวัดได้ราว 16 วินาที
ตอนเซิร์ฟเวอร์ตื่นอยู่แล้ววัดได้ราว 0.4 วินาที จึงต้องมีแผ่นทับบอกสถานะเสมอ

## หน้าจัดการข้อมูล (admin.html)

เป็นไฟล์แยกจากเว็บหลัก ไม่ได้อยู่ในเมนูและไม่ได้ใช้ตัวจัดเส้นทางเดียวกัน เปิดที่ /admin.html
ใช้ตัวแปรสีและคลาสร่วมกับเว็บหลักทั้งหมด มี admin.css เพิ่มเฉพาะการ์ด ฟอร์ม และกล่องยืนยัน

หน้าจอแบ่งตามตารางในฐานข้อมูลตรง ๆ มีสองแท็บคือ รายการยา กับ ตัวยาสำคัญ
แท็บรายการยาเป็นรายการ medicines แล้วกดเข้าไปในยาตัวนั้นทีละตัว
ในหน้ายาหนึ่งตัวมีการ์ด 6 ใบคือ ข้อมูลยา ตัวยาสำคัญ ข้อบ่งใช้ วิธีใช้ คำเตือน และยี่ห้อที่ขายยาตัวนี้
ห้าการ์ดแรกเป็นข้อมูลของสูตรตำรับ แก้แล้วมีผลกับทุกยี่ห้อ การ์ดยี่ห้อเท่านั้นที่เป็นของยี่ห้อนั้นตัวเดียว
แก้ได้ทีละการ์ด ระหว่างแก้การ์ดหนึ่ง ปุ่มของการ์ดอื่นจะถูกซ่อนไว้ กันเผลอกดแล้วค่ากรอกหาย
แท็บตัวยาสำคัญจัดการตาราง ingredients ที่ทุกยาใช้ร่วมกัน แก้ชื่อที่นี่เปลี่ยนให้ทุกยาที่ใช้ตัวยานั้น
การเพิ่มยาใหม่ใช้ตัวช่วย 7 ขั้น กรอกครบแล้วค่อยส่งเซิร์ฟเวอร์ทีเดียวในขั้นสุดท้าย
ตอนบันทึกส่งตามลำดับที่ฐานข้อมูลต้องการคือ ตัวยาสำคัญ แล้วยา แล้วยี่ห้อ

วิธีใช้งานสำหรับคนกรอกข้อมูล เขียนไว้ที่ admin-guide.md แก้หน้านี้แล้วอย่าลืมแก้คู่มือด้วย

**ต่อกับ API จริงแล้ว** ทุกอย่างในหน้านี้อ่านและเขียนผ่านเส้นทาง /admin ของ Backend
ไม่มีข้อมูลจำลองและไม่มีสำเนาในเบราว์เซอร์อีกแล้ว สิ่งที่บันทึกมีผลกับผู้ใช้ทุกคนทันที
ที่อยู่เซิร์ฟเวอร์อยู่ที่ API_BASE ใน config.js ไฟล์เดียว ห้ามเขียนที่อยู่ซ้ำในไฟล์อื่น

เส้นทางที่หน้านี้ใช้
- GET /categories · GET /admin/me
- /admin/medicines (GET, GET/{id}, POST, PUT/{id}, DELETE/{id})
- /admin/brands (GET, POST, PUT/{id}, DELETE/{id})
- /admin/ingredients (GET, GET/{id}, POST, PUT/{id})

ข้อตกลงของ API ที่ต้องระวัง
- ยาหนึ่งตัวส่งแก้ไขด้วย PUT ที่ต้องมีครบทุกช่องทุกครั้ง · medBody() ประกอบก้อนนั้นให้
  การ์ดแต่ละใบจึงส่งเฉพาะช่องที่ตัวเองแก้ทับลงไป ช่องอื่นถูกส่งค่าเดิมกลับไปเสมอ
- warnings กับ ingredient_ids เป็นแบบ "แทนที่ทั้งชุด" ไม่มีเส้นทางแก้ทีละข้อ
  หน้าเว็บจึงแก้ในหน่วยความจำก่อนแล้วส่งทั้งอาร์เรย์
- indications ฝั่งเซิร์ฟเวอร์เป็นข้อความก้อนเดียว หน้านี้ให้กรอกทีละข้อแล้วต่อด้วยขึ้นบรรทัดใหม่
  ด้วย lines() กับ unline() ถ้าเปลี่ยนตัวคั่นต้องแก้สองฟังก์ชันนี้คู่กัน
- เลขทะเบียนซ้ำเซิร์ฟเวอร์ตอบ 409 พร้อมข้อความไทย หน้านี้ตรวจซ้ำให้ก่อนตั้งแต่ในเครื่อง
  เพราะโหลด /admin/brands มาทั้งหมดอยู่แล้ว แต่ยังต้องรับ 409 ไว้เสมอ เผื่อมีคนเพิ่มพร้อมกัน
- ลบยาที่ยังมียี่ห้อเซิร์ฟเวอร์ตอบ 409 หน้านี้กันไว้ก่อนแล้วบอกให้ลบยี่ห้อให้หมดก่อน
- ลบสำเร็จได้ 204 ไม่มี body · api() คืน null ให้

**การเข้าสู่ระบบเป็นของจริงแล้ว** ใช้ POST /admin/login แบบฟอร์ม ไม่ใช่ JSON
บัตรผ่านเก็บใน sessionStorage ชื่อ admin_token มีอายุ 8 ชั่วโมง
ทุกคำขอที่ขึ้นต้นด้วย /admin แนบหัว Authorization: Bearer ให้อัตโนมัติใน api()
ถ้าได้ 401 จะลบบัตรผ่านแล้วพากลับหน้าเข้าสู่ระบบพร้อมข้อความบอกเหตุผล
ห้ามเก็บชื่อผู้ใช้ รหัสผ่าน หรือเงื่อนไขการตรวจสิทธิ์ไว้ในไฟล์ฝั่งนี้เด็ดขาด
บัญชีผู้ดูแลสร้างจากฝั่ง Backend เท่านั้น ไม่มีหน้าสมัครสมาชิก

หน้าจอมีข้อความเตือนว่ากำลังแก้ข้อมูลจริงอยู่ที่หัวหน้าจัดการ ห้ามเอาออก

กับดักของหน้านี้

- admin.js มีชุดไอคอนของตัวเอง เพราะโหลด app.js ไม่ได้ (app.js จะไปเรียกอิลิเมนต์ที่หน้านี้ไม่มี)
  ถ้าเพิ่มไอคอนในเว็บหลักแล้วอยากใช้ที่นี่ด้วย ต้องคัดลอกมาใส่ใน P ของ admin.js
- ลบยาไม่ได้ถ้ายังมียี่ห้ออ้างถึงอยู่ เซิร์ฟเวอร์ตอบ 409 และ delDrug() ดักไว้ก่อนอีกชั้น
- ตัวยาสำคัญเป็นตารางกลางที่ยาหลายตัวใช้ร่วมกัน ปุ่มกากบาทในการ์ดคือ "เอาออกจากยานี้"
  ไม่ใช่ลบออกจากระบบ ส่วนปุ่มดินสอแก้ชื่อตัวยานั้นทุกที่ที่ถูกใช้
- ปุ่มลบใช้ --danger-solid ไม่ใช่ --danger เพราะ --danger ในโหมดมืดเป็นสีอ่อนสำหรับตัวอักษร
  ถ้าเอามาเป็นสีพื้น ตัวอักษรขาวจะอ่านไม่ออก

## ความปลอดภัย

ไฟล์ฝั่งนี้ถูกส่งไปยังเครื่องผู้ใช้ทั้งหมดและเปิดอ่านได้

- ห้ามใส่กุญแจการเข้าถึงบริการใด ๆ ไว้ในโค้ดฝั่งนี้เด็ดขาด ให้เรียกผ่าน Backend เท่านั้น
- ข้อมูลที่ตรวจสอบความถูกต้องไว้ฝั่งนี้ ต้องตรวจซ้ำที่ Backend เสมอ
- รายการดูล่าสุดเก็บไว้ในเบราว์เซอร์ของผู้ใช้เท่านั้น ไม่ส่งออกไปที่ใด
