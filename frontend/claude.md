# CLAUDE.md

คำแนะนำสำหรับ Claude Code เวลาทำงานกับโค้ดในโฟลเดอร์นี้

## ภาพรวมโปรเจค

Frontend ของ "เว็บไซต์อ่านฉลากยาสามัญประจำบ้าน" (OTC Medicine Label Scanning and
Safety Verification System) — ปริญญานิพนธ์ ทีม 2 คน

ผู้ใช้ถ่ายภาพฉลากยาหรือค้นหาด้วยชื่อยา ระบบแสดงข้อบ่งใช้ ขนาดการใช้ และคำเตือน
กลุ่มผู้ใช้หลักรวมผู้สูงอายุ จึงต้องอ่านง่าย ปรับขนาดตัวอักษรได้ และฟังเสียงได้
ไม่มีระบบบัญชีผู้ใช้ทั่วไป มีแค่ Admin ที่ต้อง login เพื่อจัดการข้อมูลยา

## คำสั่งที่ใช้บ่อย

```
python -m http.server 5173 --directory frontend
```

เปิด http://localhost:5173

หรือใช้ Live Server ของ VS Code ก็ได้ ตั้งค่าไว้ให้แล้วใน .vscode/settings.json

**ต้องเปิดที่ http://localhost:5173 หรือ http://localhost:3000 เท่านั้น**
เพราะฝั่ง Backend อนุญาตให้เรียกข้ามต้นทางได้แค่สองที่อยู่นี้กับที่อยู่จริงบน Vercel

ข้อควรระวังสองข้อ ถ้าผิดข้อใดข้อหนึ่งการเรียก /scan จะถูกเบราว์เซอร์ปฏิเสธด้วยกฎข้ามต้นทาง

1) พอร์ตต้องเป็น 5173 หรือ 3000 พอร์ตอื่นเช่น 5500 หรือ 5501 ที่ Live Server ใช้เป็นค่าตั้งต้นใช้ไม่ได้
2) ต้องพิมพ์ localhost เท่านั้น ใช้ 127.0.0.1 แทนไม่ได้ ถึงจะเป็นเครื่องเดียวกัน
   แต่เบราว์เซอร์ถือว่าเป็นคนละต้นทาง ตรวจแล้วว่า http://127.0.0.1:5173 ก็ยังถูกปฏิเสธ

ถ้าจำเป็นต้องใช้ที่อยู่อื่นจริง ๆ ต้องขอให้ฝั่ง Backend เพิ่มให้ก่อน

ห้ามเปิดด้วยการดับเบิลคลิกไฟล์ เพราะเบราว์เซอร์จะปฏิเสธการอ่าน data/drugs.json
และคำสั่งเรียกกล้องกับไมโครโฟนต้องการ HTTPS หรือ localhost เท่านั้น

## สถาปัตยกรรม

- index.html — หน้าเดียวครอบทุกหน้าย่อย แต่ละหน้าเป็น section.view ที่สลับด้วยแอตทริบิวต์ hidden
- css/ — เรียง 5 ไฟล์ tokens, base, shell, components, pages
- js/config.js — ที่อยู่ของ Backend และสวิตช์เปิดปิดตัวจำลองคำตอบ
- js/data.js — โหลดข้อมูลยา จัดรูปข้อความให้ค้นได้ และอ่านเขียนที่เก็บข้อมูลในเบราว์เซอร์
- js/app.js — ไอคอน เส้นทาง การแสดงผลทุกหน้า การค้นหา เสียง กล้อง และการเรียก Backend
- data/drugs.json — ข้อมูลยาที่ใช้แสดงผลในปัจจุบัน

ลำดับการเรียกไฟล์ CSS ใน index.html ห้ามสลับ เพราะ tokens ประกาศตัวแปรสีและขนาด
ที่ไฟล์ถัดไปทั้งหมดอ้างถึง และ pages ต้องอยู่ท้ายสุดเพื่อให้ทับค่าของไฟล์ก่อนหน้าได้

เรียกไฟล์ JavaScript ตามลำดับ config.js, data.js, app.js เสมอ
เพราะ app.js เรียกใช้ค่าและฟังก์ชันที่นิยามไว้ในสองไฟล์แรก

## โครงสร้าง data/drugs.json

```
categories[]    id, name, short, icon, order
formulations[]  id, categoryId, name, genericTh, genericEn, ingredients[], indications[],
                dosage, dosageAdult, warnings[], dosageForm, dosageFormEn, packaging
brands[]        id, formulationId, categoryId, productName, licensee, regNo, legalType,
                status, statusLabel, dosageForm, dosageFormEn, packaging, override
meta            sourceNote, updatedAt, references[]
```

ยาหนึ่งสูตรตำรับมีได้หลายยี่ห้อ ข้อมูลที่ใช้แสดงผลรวมมาจาก formulation เป็นหลัก
แต่ถ้ายี่ห้อนั้นมี override ให้ใช้ของยี่ห้อแทน ฟังก์ชัน content() ใน data.js จัดการให้แล้ว
ห้ามอ่านค่าจาก formulation หรือ brand ตรง ๆ โดยข้าม content()

**ห้ามแก้ไขข้อมูลยาใน drugs.json เอง** เป็นข้อมูลที่ทีมตรวจสอบกับทะเบียนยา อย. แล้ว
ถ้าพบข้อมูลผิดให้แจ้ง ไม่ต้องแก้ให้

## กับดักที่เคยเจอมาแล้ว อย่าทำซ้ำ

- `$` และ `$$` ใน app.js เป็นฟังก์ชันที่เขียนขึ้นเอง ไม่ใช่ jQuery โปรเจคนี้ไม่ใช้ไลบรารีใดเลย
- ข้อความทุกตัวที่มาจาก drugs.json หรือจากผู้ใช้ ต้องผ่าน esc() ก่อนต่อเป็นสตริง HTML เสมอ
- สร้างข้อความ HTML ทั้งก้อนให้เสร็จก่อน แล้วเขียนลง DOM ครั้งเดียว อย่าเขียนทีละรายการในลูป
- ผูกเหตุการณ์ด้วยการมอบหมายที่อิลิเมนต์แม่ เพราะรายการยาและปุ่มกลุ่มอาการถูกสร้างหลังโหลดข้อมูล
  ถ้าผูกตรงกับอิลิเมนต์ลูกตั้งแต่ต้น จะไม่ทำงานกับของที่สร้างทีหลัง
- การเทียบข้อความค้นหาต้องผ่าน norm() และเลขทะเบียนต้องผ่าน regKey() เสมอ ห้ามเทียบตรงตัว
  เพราะชื่อยาไทยมีสระและวรรณยุกต์ที่พิมพ์ต่างกันได้ และผู้ใช้พิมพ์เลขทะเบียนไม่เหมือนกัน
- ตรวจการรองรับของเบราว์เซอร์ก่อนเรียกใช้ความสามารถพิเศษเสมอ ได้แก่ SpeechRecognition,
  speechSynthesis และ mediaDevices ถ้าไม่รองรับให้ซ่อนปุ่มนั้นไปเลย อย่าปล่อยให้กดแล้วเงียบ
- route() ต้องคืนทรัพยากรที่ค้างอยู่ทุกครั้งที่เปลี่ยนหน้า ปัจจุบันเรียก stopSpeech() และ camClose()
  ถ้าเพิ่มความสามารถที่ถือทรัพยากรไว้ ต้องเพิ่มการปิดตรงนี้ด้วย
- คำตอบที่รอนาน เช่น /verify ต้องถือตัวอิลิเมนต์ไว้เป็นตัวแปร ห้ามค้นจาก id ตอนคำตอบกลับมา
  เพราะถ้าผู้ใช้ถ่ายใหม่ระหว่างรอ คำตอบของภาพเก่าจะไปเขียนทับกล่องของภาพใหม่
- ใช้คลาสที่มีอยู่แล้วก่อนเขียนสไตล์ใหม่ โดยเฉพาะ state, state-ico, state-actions, btn, rows, notice
  หน้าตาจะตรงกับหน้าอื่นทันทีและรองรับโหมดสีเข้มอยู่แล้ว
- สีทุกสีต้องอ้างผ่านตัวแปรใน tokens.css ห้ามใส่ค่าสีตรง ๆ ในไฟล์อื่น เพราะโหมดสีเข้มจะเพี้ยน
- ขนาดตัวอักษรใช้หน่วยสัมพัทธ์เสมอ เพราะปุ่มปรับขนาดทำงานด้วยการเปลี่ยนขนาดพื้นฐานของเอกสาร
  ถ้าใช้หน่วยคงที่ ข้อความส่วนนั้นจะไม่ขยายตาม

## การเข้าถึงได้ ต้องรักษาไว้

กลุ่มผู้ใช้หลักรวมผู้สูงอายุและผู้ที่มองเห็นไม่ชัด สิ่งที่ทำไว้แล้วและห้ามทำหาย

- ปรับขนาดตัวอักษร 3 ระดับ และโหมดสีเข้ม
- ใช้งานได้ครบด้วยแป้นพิมพ์ มีกรอบบอกตำแหน่งที่กำลังใช้งาน และมีลิงก์ข้ามไปเนื้อหาหลัก
- ข้อความสถานะใช้ aria-live เพื่อให้โปรแกรมอ่านหน้าจอประกาศ
- ปุ่มที่เป็นไอคอนล้วนต้องมีชื่อกำกับด้วย aria-label
- ลดการเคลื่อนไหวเมื่อผู้ใช้ตั้งค่าเครื่องให้ลดการเคลื่อนไหว

## การเชื่อมกับ Backend

Backend ขึ้นใช้งานจริงแล้วที่ https://medcheck-api-1052579662255.asia-southeast1.run.app
ที่อยู่นี้เขียนไว้ที่ js/config.js ที่เดียว ย้ายเซิร์ฟเวอร์เมื่อไรแก้ไฟล์นั้นไฟล์เดียว
ตั้ง USE_MOCK เป็น true เมื่ออยากทดสอบหน้าเว็บโดยไม่เรียกเซิร์ฟเวอร์จริง

โครงการนี้ไม่มีขั้นตอนแปลงไฟล์ ไฟล์ถูกส่งขึ้นเว็บตามที่เขียนไว้เลย
จึงใช้ environment variable แบบ import.meta.env ของ Vite ไม่ได้ ต้องเขียนค่าไว้ใน config.js
ที่อยู่เซิร์ฟเวอร์ไม่ใช่ความลับ เครื่องผู้ใช้เห็นอยู่แล้วตอนเรียกใช้งาน จึงเขียนตรง ๆ ได้
แต่กุญแจการเข้าถึงบริการยังห้ามใส่ฝั่งนี้เด็ดขาด

ตอนนี้ฝั่งนี้เรียกสองเส้นทาง ส่วนรายการยาและการค้นหายังอ่านจาก data/drugs.json เหมือนเดิม

### POST /scan

ส่งภาพเป็น multipart ชื่อช่องต้องเป็น file ถ้าใช้ชื่ออื่นจะได้รหัส 422
ห้ามตั้งหัวข้อ Content-Type เอง เบราว์เซอร์ต้องเติมเส้นแบ่งข้อมูลให้เอง

```
match_type   reg_no | brand_name | active_ingredient | out_of_scope | not_found
ocr_text     ข้อความทั้งหมดที่อ่านได้จากฉลาก
ocr_reg_no   เลขทะเบียนที่อ่านได้ หรือ null
brand        { id, brand_name, licensee, reg_no, legal_type, medicine_id } หรือ null
medicine     ข้อมูลยาเต็มรูปแบบเดียวกับ /medicines/{id} หรือ null
candidates   [ brand + medicine_name ] เมื่อจับคู่ได้หลายยี่ห้อ
```

ฝั่งนี้ใช้ match_type กับเลขทะเบียน แล้วเอาเลขทะเบียนไปค้นใน drugs.json ด้วย brandByReg()
ไม่ได้ใช้ medicine ที่ส่งมา เพราะโครงสร้างต่างกันและข้อมูลในไฟล์ฝั่งนี้ตรวจกับทะเบียนยา อย. แล้ว
ใช้เลขทะเบียนเป็นตัวเชื่อมสองระบบ เพราะ id ในฐานข้อมูลเป็นตัวเลข
แต่ในไฟล์ข้อมูลฝั่งนี้เป็นข้อความแบบ b-001 ตรวจแล้วว่าเลขทะเบียนทั้ง 23 ยี่ห้อตรงกันทั้งสองฝั่ง

### GET /verify/{brand_id}

ตรวจสถานะทะเบียนกับเว็บ อย. ใช้ brand.id ที่ /scan ส่งมา ไม่ใช่ id ในไฟล์ฝั่งนี้
เรียกหลังแสดงข้อมูลยาให้ผู้ใช้เห็นแล้วเสมอ เพราะระบบของ อย. ตอบช้าได้ถึงประมาณครึ่งนาที
ห้ามให้ทั้งหน้ารอผลการตรวจ

อ่านคำตอบตามลำดับนี้ ok ก่อน แล้ว found แล้ว is_active
ok:false คือติดต่อ อย. ไม่ได้ ซึ่งยังได้รหัส 200 ไม่ใช่ 502

### ข้อตกลงร่วมของทุกเส้นทาง

ข้อความผิดพลาดอยู่ที่ detail เป็นภาษาไทย นำไปแสดงผู้ใช้ได้เลย
ยกเว้นรหัส 422 ที่ detail เป็นรายการ ไม่ใช่ข้อความ ฟังก์ชัน errText() ใน app.js จัดการให้แล้ว

เซิร์ฟเวอร์จะหลับเมื่อไม่มีคนใช้ คำขอแรกจึงช้าได้ 5-10 วินาที ไม่ใช่ความผิดพลาด
หน้าถ่ายรูปจะขึ้นข้อความบอกผู้ใช้เองเมื่อรอเกิน 7 วินาที

### เส้นทางที่ยังไม่ได้ใช้

/categories, /medicines/search, /medicines/by-category, /medicines/{id}
ของพวกนี้มีข้อมูลตรงกับ drugs.json ทุกรายการ ถ้าจะเปลี่ยนให้หน้าเว็บอ่านจากฐานข้อมูลแทนไฟล์
ต้องแก้ data.js ทั้งไฟล์และเตรียมทางสำรองตอนเซิร์ฟเวอร์ล่ม ยังไม่ได้ทำ

## ความปลอดภัย

ไฟล์ฝั่งนี้ถูกส่งไปยังเครื่องผู้ใช้ทั้งหมดและเปิดอ่านได้

- ห้ามใส่กุญแจการเข้าถึงบริการใด ๆ ไว้ในโค้ดฝั่งนี้เด็ดขาด ให้เรียกผ่าน Backend เท่านั้น

- รายการดูล่าสุดเก็บไว้ในเบราว์เซอร์ของผู้ใช้เท่านั้น ไม่ส่งออกไปที่ใด
